# Create an empty document — 2026-11-03

Independent Rust adaptation of cohort #24 [Thunar Create Document / Empty File](https://docs.xfce.org/xfce/thunar/working-with-files-and-folders). “New empty file” is available from the view/actions menu and command palette. It creates an unused New File.txt in the active folder and opens the existing rename dialog, with the stem selected. Subsequent names are New File 1.txt, New File 2.txt, etc. Cancel naming keeps the created file, matching Commander's existing create-folder naming workflow. No editor opens automatically; template documents remain a separate feature.

Creation uses atomic OpenOptions::create_new, never a preflight exists-then-truncate sequence. Existing regular files, directories and symbolic links are not replaced or followed; AlreadyExists retries up to 1024 candidates and all other errors stop with a notice. There is no parent-directory creation. Mutation/integrity/deletion/replay/recovery, pending-dialog and destination read-only guards apply even to direct core callers. Both live views refresh when they show the destination; an unrelated opposite pane keeps its listing state. Naming is bound to the native created path, independently of later navigation. As with existing new-folder creation, this command itself does not add an Undo entry; a committed rename uses existing rename history.

Three regressions cover both pane directions, real payload/directory/dangling-symlink collisions, zero-byte output, opposite owner preservation, same-folder dual refresh, captured rename after navigation, read-only/pending/integrity/missing-folder refusal and complete 1024-name exhaustion. The existing mutation-command matrix includes the new action. Seven gates pass: audit, build, 3553 tests (zero failed, three ignored), Clippy with warnings denied, default check, format and diff. Default check retains two preexisting warnings. Rust/Cargo and executable hashes bind evidence to the delivered source.

Native macOS QA retains every earlier Miller/tab/pin/path/picker receipt, opens the command palette, types the new command and submits it. A preexisting New File.txt retains its payload while New File 1.txt is created with zero bytes and offered for naming. Typing Draft and Enter yields Draft.txt with zero bytes and focuses that row, preserving the right pane/tab objects. Fourteen framebuffer checks pass; final frame inspected. The verifier independently checks exact paths, byte lengths, collision payload, pending naming state, unchanged tab sets/opposite pane, prior receipts and all source/executable hashes. Native view-menu activation, cancel naming and other platforms remain outside this slice; existing rename cancel behavior is reused.
