# Zstandard ZIP/ZIPX reading: methods 93 and 20

Independent integration of mholt/archives cohort #98 ZIP Zstandard support:
https://github.com/mholt/archives/blob/main/zip.go
The source registers a ZIP Zstandard decompressor. Commander’s Rust adaptation reuses the existing zstd dependency and also reads the legacy method ID 20. No Cargo dependency or version changes occur; no Go code is copied.

The shared verified ZIP adapter now has typed LZMA/XZ and Zstandard decoder variants. Method selection still uses immutable central-directory metadata. Zstandard is configured with window_log_max(26), capping each frame’s back-reference window at 64 MiB, including later concatenated frames. This is not a claim that the decoder's entire allocation or process RSS is 64 MiB; context, input/output buffers and other overhead are additional. Decode errors include the configured window bound. LZMA/XZ keep their existing liblzma memory budget and cached LZMA properties. Both decoder families share exact declared-size and ZIP CRC verification at EOF, metadata delegation and encrypted-member refusal.

Both method IDs work through archive listing/content search, integrity checks and regular/symlink extraction. Display/export labels distinguish modern Zstd from Zstd (legacy method 20). Concatenated frames and skippable metadata frames are accepted. A Zstandard checksum is optional in the frame; the outer ZIP CRC is still required. Existing byte budgets, cancellation, path guards, no-clobber extraction and partial-output cleanup remain in place. PPMd, ZIP-based document routing, archive creation and passwords remain open.

Independent fixtures are compressed by the installed zstd CLI, with Python writing ZIP records. They cover checked/unchecked/Unicode/empty content, both method IDs, legal 64 MiB window boundary, concatenation with skippable metadata, a standalone skippable frame, 128 MiB window requests in the first/later frame and legacy method, bad ZIP CRC/size, truncated/trailing data, bad frame checksum, encrypted flag, ratio bombs, traversal and symlinks. verify_fixtures.py checks container/data hashes and CLI decoding at 64 MiB. Window-refusal cases are also successfully decoded with the CLI at 256 MiB and compared with their expected hashes, proving that they are valid data outside policy rather than corrupt data. The CLI version and verification logs are preserved.

Six new Rust regressions cover those fixtures through listing, exact content/output bytes, check counts, live/indexed search, integrity byte limits/cancellation, safe/escaping symlinks and cleanup. The full suite retains the prior LZMA/XZ and standard ZIP codec regressions.
