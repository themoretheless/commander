# Minimum verified duplicate copies — 2026-10-31

Independent adaptation of [fclones replica-count selection](https://github.com/pkolaczk/fclones/blob/main/fclones/README.md#finding-files), cohort #85. Commander exposes an inclusive **Groups with at least N copies** threshold, rather than mirroring fclones CLI option names or its removal/retention-count semantics. No upstream implementation or executable is used.

The duplicate tool gains a collapsed section whose header always shows the applied minimum. **Minimum copies** stages a count, **Apply minimum** rescans the current scope, and **Reset minimum** returns to two. Empty input means two; valid values are unsigned decimal 2 through u32::MAX, at most ten digits. Invalid/unique-mode values leave results and the applied threshold unchanged and disable Apply. Scope changes, depth/name/size changes and Rescan retain the applied threshold and its separate draft; manual keeper choices are rebuilt. The threshold selects which verified groups participate in results/CSV/removal proposals; it does not increase how many copies the existing keeper policy retains, and applying it never starts removal.

After existing name/size filtering and physical-file identity collapse, size buckets smaller than the threshold are excluded from hash totals/content reads. Remaining candidates undergo the existing full verified digest comparison. Each confirmed digest group is then checked against the threshold again: equal size, a matching digest prefix, or an unreadable/disappeared candidate cannot establish N identical copies. Hard-link aliases count once when identity is available. Both listing and recursive scopes use the same threshold. Zero eligible buckets finish with zero content hashes and no candidate-failure issues; actual failures in eligible buckets retain the existing partial-scan diagnostic. This is not a benchmark or a claim of fclones performance/feature parity.

The new controls reserve vertical space by letting the group-list viewport shrink within its existing maximum, keeping the action footer reachable when scan settings are expanded. The empty result message names an active minimum above two rather than asserting there are no duplicate pairs.
