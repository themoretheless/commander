# TAR content SHA-256 groups

Independent combination of cohort #98 [mholt/archives TAR stream iteration](https://github.com/mholt/archives/blob/main/tar.go) and the existing cohort #96-inspired content comparison. Find matching contents now supports plain TAR, tar.gz, tar.bz2, tar.xz and tar.zst through Commander's existing in-process readers. No external implementation or dependency was added.

Safe regular files are grouped by SHA-256 of fully read logical content and checked size. Directories, symlinks, hardlinks and special records do not become file-body matches. Original iteration indices are retained, including duplicate TAR names; PAX long/Unicode paths use the same raw-path decoding and containment policy as listing. Existing selection mapping checks original index/path/size/type before adding matches. ZIP keeps its strict-header/unique-name and CRC/AES behavior. TAR reports retain the explicit absence of a per-file payload checksum: successful hash computation is an observation of the read data, not proof of a trusted original or a pairwise byte comparison.

The existing 128 MiB decoded-stream and logical-payload limits, 100000-member limit, 8 MiB charged identity metadata, cancellation and immutable-source stamp checks remain. Compressed trailers/later frames are consumed before a result is published. Group results are discarded on any later error/refusal. TAR listing/search now also follows data after zero blocks, and gzip listing uses the multi-member decoder, so visible entry identities agree with the complete stream scanner across concatenated archives. No files are extracted by grouping. Ordinary TAR extraction remains a separate operation.

Fixtures are independently authored with Python tarfile/PAX, gzip, bz2 and lzma, plus the system zstd compressor. The saved oracle records every member and payload SHA-256. Two Rust matrix regressions exercise all five codecs, empty/repeated contents, duplicate names, PAX names, link/folder exclusion, exact listing/scan identity alignment, no source modifications/extraction, concatenated archives/frames, later corruption, metadata/member/decoded limits and cancellation. The initial concatenation assertion forgot that the formerly singleton file becomes a matching pair across copies; the original failure is retained, and the final expectation includes all sixteen regular records.

Native ArchiveTarContentGroups uses raw pointer input to scan a gzip fixture, select seven exact matching records, expand digest/path details and copy text/JSON reports. It retains original indices across sorted listing positions and duplicate paths. The native driver restores the first group to view for the final capture. Independent Python verification checks the preserved fixture with tarfile/hashlib, both full groups, every listing identity, exact selections, visible empty-file group, untouched source/no extraction and both clipboard report formats. The existing ZIP content-group scenario is also recaptured with password/error, grouping, selection, rendering and both exports. Both scenarios use recording clipboard ports, not the OS clipboard.
