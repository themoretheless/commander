# Select a book from an FB2 ZIP collection

Extends the existing archive/book preview workflow from the cohort transfer work. Multi-book .fb2.zip files now load a bounded native BookCollection instead of failing as ambiguous. This is a Commander extension; no claim of upstream selection-format compatibility or copied implementation is made.

A collection holds member names and extracted text from a single verified outer-file snapshot. ZIP member order is retained, first book selected initially, and the Book menu chooses another loaded member without I/O or extraction. Find, line layout and Copy displayed text receive exactly that book's Arc text. Selection is owned by the collection Arc and pane, not just the path: a replacement source owner resets it. One-book ZIPs retain the original plain-text preview flow.

The pipeline has a typed TextPreviewDocument (Text or Books), with a default plain-text provider adapter for existing providers. Fingerprints, generation cancellation, worker limits, cache admission and LRU eviction remain shared. All book text and member-name bytes are included in cache accounting. PreviewContent::Books retains the collection independently of cache eviction. Refresh/toggle identity and close cancellation include the new variant. No JSON/string marker protocol or new dependencies are used.

Bounds: outer ZIP 16 MiB / 4096 entries; at most 32 eligible books and 4096 bytes per member name; combined decompressed FB2 bytes 4 MiB; combined extracted text plus names 256 KiB. Existing decoded-XML/per-book parser limits remain. Duplicate/unsafe/nonregular candidates, malformed books, encryption, CRC/read errors, or any exceeded bound refuse the complete collection; no partial collection is published. All eligible books are parsed in the worker before publication. The UI menu uses a bounded truncated selected label.

Regressions cover mixed encodings and central-directory order, count/aggregate input/output bounds, typed cache accounting and retained ownership after eviction, provider snapshot identity, actual egui menu/copy input and new-source selection reset. Preliminary compiler failures (Cow filename conversion, an exhaustive preview owner match, explicit sum type) and headless texture-delta handling are retained as development logs. They are not passing gates.

The separate native book_collection_preview scene opens two books with different text, clicks the second member through the actual menu, finds its unique message and copies the actual selected text. It retains the original ZIP, selected index/names/text and recording clipboard bytes. Single-book ZIP remains a native control. No deadline or effect-isolation assertions are weakened.

Final validation: seven regular gates passed (audit, QA build, full suite, strict all-target QA Clippy, normal check, format, diff), 3307 tests passed / 3 ignored. A final QA rebuild and focused menu test also passed after the test-harness adjustment. The collection and single-book ZIP scenes each passed 14/14 with one intercepted clipboard call and zero other effects. Independent Python ZIP/XML verification matches the actual selected member (index 1), member names and clipboard bytes. Source/executable hashes match the launch receipts. Both final frames inspected: selector and selected text/find/copy fit without overlap. Native error/oversize layouts, long-name popup edges, refresh/close/cache-eviction interaction and OS pasteboard remain open; unit/provider/cache tests cover the scoped ownership and bound contracts.
