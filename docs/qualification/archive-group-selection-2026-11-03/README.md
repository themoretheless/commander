# Per-group archive content selection

Independent continuation of cohort #96 [PeaZip checksum-group workflow](https://peazip.github.io/duplicates-hash-checksum.html), adapted to Commander's retained SHA-256 content groups. Each rendered group now has Select group and Deselect group actions. They add/remove all scanned members of that group, including hidden entries, without changing other groups or unrelated selections. The existing all-matches action shares the same selection owner. This milestone adds selection controls, not a new equality test, extraction or deletion action.

Before mutation, every requested member resolves to the original index, exact path, size and regular-file type in the retained listing. Unknown groups, stale identities or ambiguous listing indexes refuse atomically: no partial changes are applied. Selection does not reread the archive, rescan content, change filters/sorting/focus or rebuild hash groups. The existing bounded details view still renders only its first 100 groups; per-group controls apply to those rendered groups, while the global action/report includes all retained groups. A paginated group browser remains separate work.

A new Rust regression covers selecting/deselecting two groups with duplicate member paths, keeping an unrelated selection, returning to the full set and refusing unavailable/stale groups without partial mutation. Existing mapping and scan tests remain. Native ArchiveTarContentGroups extends from 20 to 36 raw pointer phases: after the existing scan/selection/view/export checks it deselects the empty group, deselects the data group, selects the empty group and selects the data group again. Each step records exact original indices and sorted-list positions, independently checked from prior Python tarfile/hashlib fixture metadata. It restores visible group details for the final capture. ZIP content-group scan/render/selection and two report copies are recaptured as a regression. No additional clipboard operations are added.

The independent TAR/codec fixtures and their hashes are reused from [TAR content qualification](../tar-content-groups-2026-11-03/README.md). Final source hashes, common gates and capture results follow below. Raw diagnostic logs are preserved verbatim via local .gitattributes.
