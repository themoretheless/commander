# Type alternatives — 2026-10-28

Independent adaptation of fd’s repeated file-type alternatives, cohort repository #77 ([primary man page](https://github.com/sharkdp/fd/blob/master/doc/fd.1)). Commander uses an explicit `types:` list so ordinary repeated `type:` conditions retain their existing AND semantics. No upstream code copied.

`types:regular,symlink` accepts either lexical type; `types:fifo,socket` combines special types. All existing type values and aliases are supported, including coarse categories such as images/folders and Commander’s broad non-directory `file`. In particular, `file` retains that broad existing meaning; use `regular` for fd-like ordinary files. A list contains 1–64 entries, empty/unknown entries are errors, duplicates preserve declaration order without duplicating hits. Whitespace around commas is accepted when the value is quoted. Multiple `types:` lists combine through AND with each other and with all other predicates. This does not implement fd’s `empty` filter, which is not yet an existing Commander type.

A nonrecursive TypeCondition enum shares single-type parsing/aliases and canonical labels with the new list. Saved JSON, expression round trips and chips retain the explicit list. Structural type labels do not influence smart-case literal evidence or require content reads. The shared observed metadata evaluator uses three-state OR logic: a proven matching branch succeeds even if another branch’s metadata is unknown; all known nonmatches reject; no match plus an unknown branch remains unresolved and contributes skipped coverage. Individual-type metadata gates remain unchanged. No index schema change or added dependencies.

Two new regressions cover alias/case/canonical/JSON forms, comma whitespace, empty/unknown/list bounds/model validation, preserved conjunctions, and known/unknown/false branch ordering. The existing real special-file native/index/ZIP/TAR fixture now tests FIFO/socket and device unions, ordinary-file/symlink unions, directory/socket unions, archive scope, AND intersections, content safeguards and filter explanations in every text mode. Legacy snapshots remove native kind, regular and symlink facts: folder or broad-file branches still establish their own results, while undecidable branches remain skipped with exact counter assertions. Existing individual-type tests continue to pass.
