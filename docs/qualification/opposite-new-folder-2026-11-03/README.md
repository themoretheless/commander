# Create a folder in the opposite pane — 2026-11-03

Independent Rust adaptation of cohort #2 [Nimble Commander Create Directory in Opposite Panel](https://magnumbytes.com/whats-new/), documented with Shift+F7. Commander's new **New folder in other panel** palette/menu action and **Shift+F7** create beside the other pane's current entries while keeping the source pane active and its picked files intact. Existing F7 still targets the current pane.

Both actions share the existing collision-free `New Folder`, `New Folder 1`, … create-then-rename workflow. The rename modal owns the actual created native path, so subsequent source navigation/focus changes cannot retarget it. The writable policy belongs to the destination: a read-only source can create in a writable opposite pane; a read-only destination, integrity stop or unavailable directory refuses. The shared core now enforces the destination policy even for direct callers. The source's live listing is not refreshed unless it shows that same directory; both same-directory views update. Only the destination cursor is moved to the new row. Background tab groups and source view/selection metadata remain unchanged.

This retains Commander's existing semantics: creation happens before the rename editor opens; cancelling the editor leaves the new folder. Directory creation itself does not gain undo; an applied name change uses existing rename history. It does not redirect creation into a highlighted subdirectory or a virtual archive member; the opposite pane's current filesystem directory is the destination.

Three new core regressions cover both source directions, preserved listing generation/cursor/selection/tab snapshot, occupied names (including a file collision), captured rename after source navigation, same-directory pane refresh, writable-target policy with read-only source, target refusal, missing destination and integrity stop. Existing shortcut mapping and mutation-classification tests now include the new action. Seven final gates passed: audit, build, 3539 tests (0 failed, 3 ignored), Clippy, default check, formatting and diff. Default compilation retains its two preexisting warnings; feature Clippy is clean.

Native macOS Miller QA retains the prior navigation/menu/tab/drag/pin checkpoints, then emits actual Shift+F7 from the right source pane, verifies a new folder and captured rename in the left destination, names it through the rename field and commits with Enter. Three independent receipts verify the destination path and unchanged source path/cursor/three-item selection/focus (including unchanged generation at initial creation), absent corresponding source folders, and disappearance of the placeholder after rename. All 14 native framebuffer checks passed with zero external native effects; final image inspected. Reverse direction, menu/palette invocation and policy refusal are core/unit-qualified; broader native platforms remain open.

It requests continuous repaint so macOS background-window timer deferral cannot suspend its driver, and starts injecting actions only while the owned window has focus. Prior failed native runs and their diagnostics are retained.
