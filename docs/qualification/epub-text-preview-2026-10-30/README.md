# EPUB spine text previews — 2026-10-30

Independent Rust adaptation of [ranger EPUB text previews](https://github.com/ranger/ranger/blob/master/ranger/data/scope.sh), cohort repository #30. ranger invokes a converter for EPUB. Commander reads package metadata and chapter text directly using existing ZIP/XML/HTML libraries; no subprocess or upstream implementation copied.

META-INF/container.xml selects the first supported OPF rootfile. Manifest IDs map spine itemrefs to UTF-8 HTML/XHTML resources, in declared order rather than ZIP/filename order. Relative and percent-encoded part names are normalized inside the package. Missing IDs/resources, duplicate manifest IDs, external or escaping paths and unsupported spine media types reject the request without publishing a partial book. Optional encryption metadata rejects selected encrypted chapters; unrelated obfuscated fonts do not block readable text and are never loaded.

Each chapter has a numbered heading followed by static body text. HTML tokenization decodes named/numeric entities, preserves inline word boundaries, paragraphs, tables and preformatted whitespace, and ignores document head, script/style/template/iframe/object/SVG/MathML content. Images become inert placeholders. Link attributes, styles and embedded media are never opened. Chapter HTML is tokenized, not executed or rendered as a browser. The output uses the existing text preview with find/copy/size/wrap controls and an EPUB text-only label. EPUB classifies as Documents. Document failure wording now covers both Office packages and books.

The existing worker/cache/request ownership and before/after file identity checks are retained. Limits: 16 MiB compressed package, 4096 entries, 4 MiB aggregate requested OPF/container/encryption/chapter data, 512 spine entries and 256 KiB output. XML metadata uses DTD-disabled parsing, node/depth caps; each chapter limits tokens to 100000 and tracked nesting to 128. Reads, decompression and token walking check cancellation. Budgets reject excessive output rather than advertising a truncated result as complete.

Five new regressions verify reversed spine order, encoded filenames and Unicode; HTML entities/inline text/table/preformatted whitespace and hidden content; external/escaping/missing/invalid paths and spine items; encrypted chapters versus unread font resources; cancellation, malformed metadata/missing body and depth/output limits. Existing classification coverage includes EPUB. Native EPUB readiness requires exact two-chapter text, one find match and one exact recording copy. The fixture is a minimal generated package, not a full external EPUB conformance corpus.

Limits: static text, not an ebook layout engine. No pagination, cover/media display, CSS, scripts, DRM decryption or rich SVG/MathML text. UTF-16 chapter encodings, DAISY/DTBook and image-only spine items are unsupported. All declared spine itemrefs are included, including nonlinear entries; alternate renditions and navigation documents outside the spine are not traversed. Broader viewer/peer parity remains open.
