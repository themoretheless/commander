# Bounded PPMd8 ZIP/ZIPX reading

Independent integration of PeaZip cohort #96 PPMd ZIP support:
https://peazip.github.io/zip-files-utility.html
Parameter format reference: https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT (section 5.10).

ZIP method 98 uses ppmd-rust 1.5.2, a Rust port of PPMd8/PPMdI rev.1. Its CC0 licence option and original-author acknowledgements are preserved in data/licenses and THIRD_PARTY_LICENSES.md. The lock adds this one package with no transitive dependencies; the zip-rs unbounded PPMd feature remains disabled. The shared reader consumes the two-byte parameters once, validates order 2..16 and restoration modes Restart/CutOff, and rejects model arenas above 64 MiB before constructing the decoder. This bounds the arena, not all decoder/process allocations: tables, context and I/O buffers are additional. Freeze restoration mode 2 and unknown modes fail explicitly.

PPMd decoding shares metadata delegation, exact uncompressed-size and ZIP CRC checks with the existing bounded adapters. Encrypted entries fail before decoder creation. A raw-input wrapper preserves premature EOF as InvalidData instead of letting the generic PPMd reader treat UnexpectedEof as successful partial termination. This is deliberate ZIP interoperability behavior: independent 7-Zip rejected a correctly sized/CRC'd stream encoded without its end marker. That stream is retained as a negative fixture, and the adapter must reject it rather than merely stop at the declared byte count. Empty valid PPMd data remains accepted.

Independent standard payloads are compressed by the official 7-Zip 26.05 macOS console release. It is downloaded/executed only in an owned temporary tooling directory, not shipped or installed as an app runtime dependency. oracle.json records the source URL, binary hash and version. Rust make_stream.rs produces empty, small symlink and negative no-marker cases because 7-Zip chooses Store for inputs whose PPMd output is larger. Those helper-produced streams are independently decoded/checked by 7-Zip. Fixtures are repacked with deterministic ZIP records and hashes; Rust tests need no external executable. Regeneration requires SEVEN_ZIP plus Cargo's cached ppmd-rust 1.5.2; the standalone fixture helper builds in a disposable temporary directory.

Fixtures cover normal and Unicode/empty content, the accepted 64 MiB arena boundary, a valid 65 MiB arena refused by policy, CutOff parameter acceptance, invalid order/restoration/Freeze, bad CRC/size, truncated header/payload, missing end marker, encrypted flag, ratio bombs, traversal and symlinks. The short CutOff fixture qualifies header/decoder compatibility, not exhaustive restoration behavior under model exhaustion. verify_fixtures.py compares 7-Zip-decoded bytes to independent expected hashes, checks error cases, and confirms the over-policy 65 MiB stream is valid for the external decoder. The arena's 256 MiB encoded maximum is also rejected in a Rust parameter test without allocating it.

Seven new Rust regressions cover those contracts through actual listing/content reads, integrity checks, regular/symlink extraction, repeated-extraction preservation, live/indexed ZIP/uppercase-ZIPX search and cancellation/decoded-byte limits. Other ZIP codecs retain their previous checked paths. Document-reader routing, PPMd archive creation, Freeze restoration and password extraction remain open.

Native ArchiveMetadata extends from 30 to 33 pointer phases and raw-copies a 7-Zip-produced PPMd member into the fixture. Ten fixed observations require all eight rendered fields visible. Final verification checks the exact PPMd label and byte size, previous nine states, native gates/effect isolation and final-build hash equality. The final PPMd framebuffer was visually inspected. An initial staging record made while the build was still running was superseded before launch; only the final post-build receipt is used for qualification. Native capture qualifies opening/display/scrolling; byte extraction is qualified by Rust integration fixtures and 7-Zip expectations.
