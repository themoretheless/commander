# Legacy SHA-1 checksums and checkfiles

Independent adaptation of cohort entry 96, PeaZip's multi-algorithm file tools (https://peazip.github.io/verify-checksum-hash.html). Uses RustCrypto sha1 0.11.0 (https://docs.rs/sha1/0.11.0/sha1/) with its bundled MIT attribution. SHA-1 is legacy interoperability only, not authentication; SHA-256 remains the default. No upstream application implementation was copied.

Adds SHA-1 to the existing single-pass file hashing lane, report rows, explicit expected-digest comparison, detailed reports, digest copying and GNU binary-mode checkfile export. Streaming/chunk/cancellation/source-handle and post-read identity guards remain shared. A digest is published only after the same successful completion as the other algorithms. The authoritative Algorithm::ALL list feeds both GUI selectors and auto detection.

Checkfile verification recognizes SHA1/SHA-1 BSD tags, SHA1SUMS filenames and .sha1/.sha1sum extensions, plus unambiguous untagged 40-digit GNU rows. Tagged/layout/mixed-algorithm rejection, 1 MiB/10000 record bounds, relative-root confinement, no symlink following and stop/progress remain shared. 64-digit SHA-256/BLAKE3 ambiguity stays explicit. One algorithm per list; no URI/network verification or file modification added.

Regressions include empty/abc/million-a vectors, uppercase expected comparisons and length rejection, exact exported rows, shasum -a 1 interoperability, relocated relative lists/special names and mismatch detection. List tests exercise GNU/BSD/filename/auto paths, mismatch and misleading/mixed metadata. Existing OpenSSL tagged-list tests include SHA-1. Initial test compilation required adding the new None field to one old full ChecksumRow fixture; initial logs retained. Detailed-text fixtures now include the new field.

The extended native Checksums workflow retains all previous algorithms and adds actual SHA-1 selection, expected-value input, digest/absolute-list copying, relative-mode switching and relative-list copying. Its final state requires an exact matching SHA-1 value and 16 total recorded clipboard writes; other effects must be zero. Actual SHA-1 clipboard payloads and source fixture are retained for independent verification. Native SHA-1 list-import interaction remains separate from this hash/export scene.

Cargo adds only sha1 as a new package; resolver selection for tempfile reuses pre-existing getrandom 0.4.3 instead of 0.3.4. License policy and advisory waivers are unchanged. The initial audit and current audit both pass all four sections after the preceding dependency repairs.

The pre-auto-expectation run retained 3308 passed / one old assertion failure: the old detector test treated SHA1 as unsupported. Its rejection case now uses unsupported SHA3-256, while SHA1/40 digits joins the accepted auto-detection table. Mixed-algorithm and SHA-256/BLAKE3 ambiguity assertions remain unchanged.
