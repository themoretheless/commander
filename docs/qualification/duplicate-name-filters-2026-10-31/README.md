# Duplicate scan name filters — 2026-10-31

Independent Rust adaptation of [fclones basename selection](https://github.com/pkolaczk/fclones/blob/main/fclones/README.md), cohort #85. Its `group --name` behavior inspires scan-time selection; Commander uses its existing globset dependency and existing duplicate scanner rather than invoking/copying fclones.

The duplicate tool gains a collapsed **Name filters** section with **Include names**, **Exclude names**, **Match name case**, **Apply name filters** and **Reset name filters**. Each nonempty trimmed line is one basename glob. Includes are ORed; an empty include list accepts any name, and exclusions win. Patterns support globset syntax, e.g. `*.{jpg,png}`, `report-?.txt`, classes and escaping; this does not claim fclones' full Bash extended-glob grammar. Matching is case-insensitive by default through globset, with an explicit sensitive option. The retained native basename is passed to the matcher without lossy display-name conversion. Patterns containing `/` are rejected: this is filename selection, not directory pruning/path filtering.

Drafts do not retarget current groups or removal choices. Invalid syntax, over 4096 combined UTF-8 pattern bytes or over 64 combined nonempty patterns disable Apply with an error; no invalid pattern silently broadens selection. Compilation is cached against the draft rules. Apply starts a fresh background hash scan under the existing scope, retaining size limits, keeper policy and sorting, and rebuilding manual group choices. Reset clears both draft/applied name rules and rescans if the applied policy changed. Applied-name captions stay visible when the section is collapsed. Rules survive Rescan, size changes and recursive scope changes within this tool opening; they are not restart-persisted preferences.

Both listing-scope and recursive workers apply names and size limits before size grouping/hash totals/content reads. Listing entries are now supplied before inode collapse so a matching hard-link alias cannot be lost behind an excluded name; identity collapse runs after filtering. Recursive traversal still descends directories regardless of name patterns, excludes symlinks, and collapses observed physical-file identities. Existing hash verification, cancellation, partial-scan reporting, CSV/removal owners and nonempty-file policy remain. The ordinary scope still consumes the pane's retained listing metadata; recursion enumerates afresh. This adds no performance/speedup claim, arbitrary tree exclusion, link-following option or destructive automation.

Three new regressions cover include union/exclusion precedence/case/basename rules, invalid/oversized patterns and no broad fallback, and real pane/tree workers with excluded disappeared files, hard-link aliases, hash counters, size bounds and descendants inside a nonmatching directory. The existing rescan regression now verifies applied name rules and an invalid uncommitted draft survive together while current scan results remain bound to the applied policy.
