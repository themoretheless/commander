# Bounded LZMA ZIP/ZIPX reading

Independent adaptation of PeaZip cohort #96 LZMA ZIP support:
https://peazip.github.io/zip-files-utility.html
https://peazip.github.io/zip-file-format.html

ZIP-LZMA member decoding uses the existing xz2/liblzma dependency with a 64 MiB decoder memory limit. There are no Cargo dependency or lockfile changes. zip-rs' unbounded LZMA feature stays disabled: a new shared zip_reader adapter reads the raw member's nine-byte ZIP-LZMA header, validates its properties size and dictionary bound, and supplies those same cached properties to a bounded LZMA-Alone stream. This prevents a second read of changed dictionary properties before allocation. The decoder itself enforces the complete liblzma memory budget, including probability tables, so even a 64 MiB dictionary cannot evade the budget through state overhead. Unsupported liblzma property combinations fail explicitly.

The adapter retains zip-rs member metadata through shared-reference delegation; it does not expose mutable access that could bypass decoded reads. Stored/Deflate/BZip2/Deflate64 retain zip-rs decoding. Archive content search, integrity checks and extraction all use the adapter; the symlink extraction path also reads through it. Listing names and metadata stays a raw read-only operation and displays Lzma as the known supported method. Encrypted LZMA entries are rejected before their payload header is read.

ZIP bit 1 controls EOS semantics. Marker-bearing members use unknown stream size and must provide an end marker; known-size members without that bit can finish at the declared byte count. The adapter verifies exact uncompressed size and CRC at EOF and rejects output beyond the declared size. Existing archive content budgets, cancellation, traversal checks, selection identity, no-clobber extraction and error cleanup remain in place. This is scoped to Commander’s archive inspection/search/extraction paths, not other ZIP-based document readers or LZMA archive creation. XZ/Zstandard/PPMd inside ZIP and passwords remain open.

Python zipfile's LZMACompressor independently supplies normal payloads and ZIP-LZMA properties. An actual no-EOS stream is produced by the fixture-only make_no_eos.c helper via liblzma's LZMA1EXT encoder with end markers disabled; stripping an EOS suffix did not make a valid completed no-marker stream, so no such shortcut is used. Fixtures and manifests are committed; Rust tests require no C compiler. Regeneration uses cc and pkg-config for the installed liblzma. verify_fixtures.py checks bytes/hashes and normal CRCs, independently decodes through Python/liblzma, proves actual lack of EOS, and rejects missing promised EOS/truncation. It inspects forged dictionary headers without decoding them, avoiding unbounded allocation in the external verifier.

Eight new Rust regressions cover EOS/no-EOS including Unicode/empty entries, exact bytes and repeat-extraction preservation, bad CRC/size/truncation/properties, 4 GiB dictionary refusal, full decoder-state memory overhead, missing required EOS, encrypted-member refusal, traversal and safe/escaping symlinks, compression ratio and cancellation, live/indexed Unicode member search, decoded-byte check limits, and cached-header integrity after an in-place dictionary mutation before the first decode.

ArchiveMetadata extends from 18 to 21 actual pointer phases, retaining the prior five metadata states and finally clicking a new LZMA member raw-copied from the independent fixture. Read-only observations require eight actual rendered fields to be visible. verify.py checks six fixed states and the exact LZMA payload size, common native checks and captured/final binary hashes. Native capture qualifies display/opening; byte extraction is covered by Rust integration tests.
