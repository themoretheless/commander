# Changes within diff lines — 2026-10-31

Independent Rust/egui adaptation of [Double Commander's Line Differences option](https://doublecmd.github.io/doc/en/help.html#cm_CompareContents), from the existing 99-repository cohort. No upstream implementation was copied.

The Diff tool now offers **Highlight changes within lines**, off by default. Within each contiguous change block it pairs deleted/inserted lines in their original order and computes a character LCS after stripping shared prefix/suffix. Changed Unicode scalars are marked with a tinted background and underline; unchanged text retains the existing row style. Unpaired inserted/deleted lines are marked in full. This is ordinal line pairing, not an optimal multiline alignment or a grapheme/word diff.

Highlight ranges refer to original UTF-8 byte boundaries, and rendered selectable text is unchanged, including the existing line markers. They compare original display text, so a remaining changed row can also expose original case/spacing differences even with comparison options enabled. Shared rows are never marked. Nothing is written to either input file.

The cache is rebuilt only on enable/disable, comparison-option changes or Reload, and is shared by full/compact rendering and navigation. The enabled preference survives those recomputations; read failures and equivalent inputs clear stale ranges. Work is bounded to 65,536 LCS cells per paired line and two million cells per rebuild. A pair exceeding either limit keeps the exact shared prefix/suffix and marks its remaining middle span; the toolbar reports the count of such simplified pairs. Pure insertions/deletions need no matrix. Existing file-read and line-diff limits remain.

Four new regressions cover multiple Unicode edits and byte boundaries, empty/identical/long/exhausted-budget cases, context-isolated pairing/unpaired rows, and exact layout text with original character markings and cache retirement on recomparison/read failure. A dedicated native scene clicks the control on/off/on, retains intermediate states, and requires exact final character spans with unchanged line counts/source coordinates. The scene is included in CI and the stable registry.
