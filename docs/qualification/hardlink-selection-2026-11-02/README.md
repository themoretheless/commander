# Select the cursor's visible hard-link group

Independently adapts the hard-link group distinction from [rmlint hardlinked-file handling](https://github.com/sahib/rmlint/blob/master/docs/rmlint.1.rst), cohort #86, as an additive Commander selection action. No upstream implementation copied; no duplicate-removal policy is imported.

**Select hard-link aliases of cursor** adds the cursor and its visible regular-file aliases to selection. The key is the complete retained device/inode pair; equal inode numbers on different devices do not match. Both objects must have positively captured regular-file identities. Directories, symbolic links, special/unknown kinds and incomplete identities do not qualify. A different visible path must match the cursor before the action can run; one visible group member alone does not cause selection. The palette uses the same condition in its existing single-pass context scan.

Existing and hidden picks remain selected; repeated invocation is idempotent, the cursor stays in place, and current ordering/filter policy controls the scope. Listing JSON naturally exports visible selected aliases while reporting hidden selections. No stat, hash, content read, recursive search or operation plan is performed. This is a convenience over listing observations: identities can be reused or become stale, and later file operations still require their own checks. It does not locate aliases outside the visible listing or estimate freed disk space.

## Validation

Three regressions cover real hard links versus byte-identical copies and symbolic links, hidden selection preservation, idempotence, a filtered-out peer, parent cursor, retained facts after source removal, full-width/device-separated/incomplete identities and regular-kind requirements; and palette/workspace context and dispatch. Native hardlink_selection selects through the palette and copies one intercepted JSON listing. Independently captured raw device/inode/link facts distinguish the two selected paths from the copy and link. Existing inode_sort is the neighboring native regression. Source/binary/checksum-oracle hashes bind acceptance. Native Windows hard-link identity coverage and global alias discovery are not established.

Final validation: all six checks passed; **3150 tests passed / 3 ignored**. Native hardlink_selection and inode_sort each passed **14/14** on the same source-bound binary. The new scenario performed exactly one intercepted clipboard write; all other external effects were zero. Independent raw device/inode/link facts matched the selected names and JSON values; the six neighboring inode/name orders also matched. Both final images were inspected. The ordinary non-QA check retains the pre-existing unused-response warning in diff_find.rs. Full parity with the original 99 repositories remains open.
