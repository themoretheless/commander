# PPTX and ODP slide text previews — 2026-10-30

Independent Rust adaptation of [ranger ODP text previews](https://github.com/ranger/ranger/blob/master/ranger/data/scope.sh), cohort repository #30. ranger delegates ODP to a text converter. Commander implements ODP directly in Rust and additionally supports PPTX through the same bounded Office text pipeline. This does not claim ranger supports PPTX. No upstream code copied or converter process invoked.

PPTX follows the presentation slide-ID list and its internal slide relationships, rather than numeric IDs, ZIP order or filenames. Strict/transitional PresentationML and DrawingML namespaces are supported independently of prefixes. The preview shows numbered slide headings, optional names, text runs/paragraphs/breaks and table-cell text. Missing relationship IDs, duplicate relationship IDs, external requested slide relationships, wrong relationship types, missing parts and escaping package targets fail without publishing partial output. Hyperlink attributes, layouts, masters, notes and media parts are not followed.

ODP follows draw:page children of office:presentation in document order. It shows slide names and body paragraph/list/shape/table text, preserving explicit spaces, tabs and breaks. Speaker notes, annotations, scripts and embedded binary data are excluded. Both formats remain plain text using existing find/copy/size/wrap controls. Hidden slides are included in presentation order. Reading order within each slide follows its XML shape order, not visual positions.

Shared Office helpers now own DTD-disabled XML parsing with 100000 nodes and depth 128, plus safe internal part-target normalization. XLSX reuses them and all previous Office regressions remain in the full run. Budgets remain: 16 MiB compressed package, 4096 entries, 4 MiB aggregate requested XML and 256 KiB extracted text. Presentation count is limited to 512 slides. Cancellation is checked during reads/decompression and text traversal. The existing worker ownership, cache and file-identity guards remain; no additional dependency.

Five new regressions cover equivalent two-slide Unicode/table output for both formats, a PPTX slide list deliberately reversing filename order, strict namespaces, entities/runs/breaks/unnamed slides, ODP spaces/lists and note/comment exclusion, invalid/missing/duplicate/external/escaping references, cancellation, slide/output budgets and malformed XML. Full locked visual-qa suite: **2689 passed, 0 failed, 3 ignored**. Native scenarios require exact two-slide text, one find match and exact copied output. Fixtures are minimal generated packages, not an external Office compatibility corpus.

Limits: text only, not slide rendering or slideshow playback. No typography/layout/image/chart/animation fidelity, notes preview, master placeholders or linked resources. ODP table repetitions are not expanded. XML parts must be UTF-8. Unsupported/encrypted/malformed documents report the existing document error. Large/image-heavy decks exceeding the package cap are refused. Broader viewer/peer parity remains open.

Integration follow-up: ODP and ODS now classify as Documents, so Docs facets and selection summaries recognize them alongside PPTX/XLSX. The existing classification regression was extended to all four formats; the full suite was rerun after this change and remains 2689 passed / 3 ignored.

Final validation: all-target Clippy with warnings denied, locked visual-qa build, cargo fmt --check and git diff --check passed. Fresh CUA-launched PPTX and ODP captures each passed **14/14**, one recording clipboard write of exact expected slide text and all other effects zero. Both manifests postdate their launch records and use the same binary. Both frames inspected: two slide headings, Unicode body, table text, one highlighted match and copy confirmation visible; speaker notes absent. No commit or push; remaining feature-transfer scope stays open.
