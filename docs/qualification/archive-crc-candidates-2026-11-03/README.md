# Select repeated declared CRC and size

Independent adaptation of cohort #96 [PeaZip archive checksum grouping](https://peazip.github.io/duplicates-hash-checksum.html). Select repeated CRC + size adds visible regular ZIP/ZIPX records whose declared CRC-32 and uncompressed size occur on another visible record. This is candidate selection using archive metadata, not payload-verified deduplication or a deletion proposal. It performs no member reads and accepts no password. Corrupt or unsupported-codec entries can still be candidates from declared metadata.

Unavailable CRCs (including AES AE-2), symlinks, directories, special records and synthetic navigation folders do not match. Zero CRC and zero-size regular files remain valid. Distinct entries with identical paths keep their own listing IDs. Duplicate/stale IDs in a supplied visible list cannot manufacture a pair. Hidden selections are preserved, while hidden entries do not create visible pairs. The action does not change filtering, sorting or focus. Group counts are computed only when clicked, using at most the already bounded visible listing, and result IDs retain displayed order. TAR does not expose the action.

A new Rust regression exercises known/zero/unavailable CRCs, unequal sizes, repeated paths and stale/repeated IDs, symlinks/directories/special entries, filtered visibility, hidden-selection preservation and TAR refusal. Native ArchiveMetadata preserves all eleven metadata states and both CRC header sorts, then clicks Clear and Select repeated CRC + size through raw pointer input (52 phases). It records the resulting visible identities, sizes, CRCs and selected IDs. Independent Python verification recomputes exact groups using separately checked metadata, excluding the AES member and all singletons. ArchiveExport rechecks five exact recording clipboard copies.
