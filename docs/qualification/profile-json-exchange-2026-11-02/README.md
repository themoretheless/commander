# Reviewed workspace-profile JSON exchange

Continuation of the Krusader-inspired profile workflow. This is Commander's own data-only format, not krusaderrc or another manager's configuration compatibility.

Workspace profiles -> Import / export JSON opens a separate exchange screen. Copy selected profile JSON exports the selected stored record, never the current panels or edited text. Paste a document, Review import JSON to inspect its roots, filters, policies and tab paths, then Add reviewed as new profile. Review has no filesystem mutation. Add re-decodes the current text and requires the reviewed profile to match, refuses existing names and uses the same stale-editor/atomic-store boundary. Applying the imported layout is a separate action from the main profile list. Invalid review clears any older candidate. Current folders and tabs do not change on review/add/export.

The commander.workspace-profile version 1 envelope includes a platform family and one profile. Input/output are limited to 1 MiB; the existing profile layout and store limits also apply. Unknown envelope/profile fields, repeated object keys at any depth, malformed/deep JSON, unsupported versions/platforms, invalid names/roots/layouts and excessive size are refused. Existing trusted-template names remain metadata; neither exchange nor profile application executes templates or grants runtime trust. No path rewriting or directory probes occur during decoding.

Three new regressions cover full-layout/metadata round trips without path probing, schema/duplicate/depth/size rejection, export refusal, non-mutating review, required re-review, explicit collision refusal and disk preservation. Native profile_exchange starts with a saved Work record while the current panels point elsewhere. It copies Work, pastes/imports a different Imported record through the actual TextEdit and Review/Add buttons, copies Imported, then rejects malformed text. Actual clipboard payloads, disk envelopes and review/add/error snapshots are retained. Expected disk generations: 1 before Add, 2 after Add, unchanged after rejection. The prior full-tab restoration scene is the control. QA's temporary storage override isolates all writes; the clipboard is the recording port, not the OS pasteboard.

The feature does not import a whole book, overwrite a name implicitly, translate platform paths or auto-apply a profile. Native settings-entry/back navigation, stale-import feedback and process restart remain additional coverage. No dependencies changed; previous dependency audit failures and the wider 99-repository transfer goal remain open.

Validation: all six gates passed (build, full tests: 3,272 passed / 3 ignored, strict Clippy, ordinary check, formatting and diff whitespace). Reviewed JSON exchange native workflow passed 16/16, prior full-tab restoration control 14/14. Independent verification matched both actual clipboard documents, preview ownership, byte-identical store before Add and after malformed review, generation 1 -> 2 only on Add, exact imported profile and unchanged current roots. Both final screenshots were visually inspected. Exchange records two clipboard calls and all other native effects zero; the control has zero native effects. Source/binary/validator hashes agree. Both scenarios are included in CI; native-launch.json and profile_tabs-launch.json select final captures.
