# Directory-only search exclusions — 2026-10-28

Independent adaptation of Double Commander Find “Exclude subdirectories” ([primary documentation](https://doublecmd.github.io/doc/en/findfiles.html)), from the 99-repository cohort. No upstream code copied. Commander implements name masks here; upstream relative/absolute path-mask exclusions remain outside this field.

New excludedir: masks skip matching directories and descendants, while files and symbolic links with the same name remain eligible. The root's own name is exempt. Masks match whole names using the existing Unicode-aware * and ? compiler, quoted spaces, default case-insensitive behavior and case:sensitive. Multiple masks exclude any matching directory. Empty, path-containing and oversized masks are rejected. Existing exclude: still prunes matching entries of any kind; excludefile: still filters only non-directory results. Saved query expressions, JSON, chips and explanations retain the new predicate.

The native jwalk read-directory filter removes matching lexical directory entries before traversal. Indexed search checks stored directory kind and lexical ancestors without live stat. Archive search checks stored member kind and member-path ancestors, including directories without explicit headers. Metadata matching also rejects matching directory leaves. Archive virtual container components are not treated as directories: bundle.zip and its synthetic bundle.zip! prefix do not suppress member search under excludedir:*.zip / excludedir:*.zip!. Real directories with either spelling are still excluded. Archive providers retain their bounded parsing/text-loading behavior; this change does not claim to avoid reading excluded member payloads or improve archive performance.

Four focused regressions cover expression/JSON round trips, invalid masks, case policy, named files retained beside matching folders, all text modes across native/index/ZIP/TAR, a root-name exclusion, explicit ZIP and implicit TAR directory ancestors, quoted spaces, archive-container scope and native symlink-to-directory own-kind behavior. The final full suite uses a JSON-roundtripped index in the main provider matrix. No index schema change is needed because directory kind already exists in old snapshots.
