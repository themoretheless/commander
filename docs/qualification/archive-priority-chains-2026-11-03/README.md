# Ordered tie breakers for archive keepers — 2026-11-03

Independent adaptation of cohort #85 [fclones priority chains](https://raw.githubusercontent.com/pkolaczk/fclones/main/fclones/src/config.rs). The main archive keeper priority can now be followed by up to five distinct tie breakers, using all six available ordering rules. Each later rule is evaluated only when earlier rules compare equal; the lowest original entry number is the final fallback. Known timestamps precede missing timestamps. First/last already distinguish unique original indices and therefore leave no ties for later rules.

The Break ties editor adds, moves and removes criteria without changing selection until Select copies. Choosing a new main rule removes it from the tie list. Malformed in-memory or saved duplicate/oversized chains refuse before selection changes; valid chains remain shared by group/global actions, replica counts, protection/candidate policies and date restrictions. Chains are remembered across archives/sessions. Older version-1 saved policies missing tie_breakers restore with an empty chain; other saved fields retain their values.

The Rust matrix contrasts primary-only stable ordering, two/three-level ordering, reordered criteria, missing times, replica counts, protected and candidate subsets, both action scopes and atomic invalid-chain refusal. Existing preference round trips now include nonempty chains; atomic session save/load includes a chain. A dedicated short archive_priority_chains scene retains the old scenes unchanged and drives add, reorder, remove and apply, checks nine exact pending/applied receipts, then saves/restores the chain through the session store and rescans the reopened archive with empty selection/history. The registry contains 144 scenes. verify.py independently ranks captured TAR members by tuple keys and compares policy, listing IDs, selections and persisted values.
