# Duplicate grouping by name components

Independently adapts [rmlint --match-basename, --match-without-extension, --match-dirname and --case-insensitive](https://github.com/sahib/rmlint/blob/master/docs/rmlint.1.rst), cohort #86. No upstream implementation copied.

Duplicate files → Name filters → Group by now offers Any name, Same full name, Same name without extension, and Same parent folder name. Optional Ignore ASCII grouping case is independent from name-glob case and extension-group case. Choices are drafts until Apply name filters, which restarts the captured scope and rebuilds keep decisions. Reset clears both name-component and extension constraints. The applied summary remains visible outside the collapsed controls; JSON records applied component/case independently of drafts.

Partitioning follows full-content digest confirmation. It compares exact native bytes (or ASCII-folded bytes), preserves member/group order, reapplies the minimum-copy threshold, then reapplies cross-root membership. Extension and component constraints combine through AND. Parent means only the immediate folder name, not its full path. Stem removes only the last extension, preserving dotfile and multi-extension semantics of Rust Path. Missing components never match one another. Different contents never become duplicates due to a shared name. Unknown parent, Unicode case, and non-UTF-8 distinctions are explicit regressions. Cancellation drops unpublished output.

Existing physical-identity collapse chooses one eligible representative per object before grouping; aliases do not become independent duplicates. Existing Trash validation remains unchanged. This does not implement unmatched-name grouping, relative-path grouping, all rmlint hard-link policies, or reclaimable-storage accounting, and does not promise fewer hash reads.
