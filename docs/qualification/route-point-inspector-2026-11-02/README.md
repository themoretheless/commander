# Route point hover inspector

Commander extension of the Strata-inspired route preview. Hover within 12 logical UI points of a recorded map point to highlight it and show point/segment number, latitude/longitude, cumulative recorded distance, elevation and timestamp. Missing elevation, absent time and invalid time remain distinct. Coordinates are displayed to six decimal places and distance to one decimal; the Source view retains original precision/text. No interpolated points or line-segment samples are created. Nearest-point ties, including coincident coordinates, choose the first recorded point deterministically; cycling coincident samples and keyboard point navigation remain open.

Hit testing uses the same projected screen positions as painting, including date-line handling and existing segment gaps. Only visible route geometry participates; no new filesystem/network reads occur. The tooltip belongs to the current cached Route and therefore shares existing source identity/cancellation behavior. Bounded route size remains unchanged.

Two regressions cover hit radius boundaries, deterministic ties/empty input, segment ownership and valid/missing/invalid metadata presentation. Existing native GPX/KML Source/Route scenes now move the pointer to an actual rendered sample and wait for tooltip content. Labels are captured inside the actual tooltip UI closure, not manufactured by the QA script. Independent verification compares them with captured original route points and source-verified geometry/timestamps/elevations. GPX targets point 2 in segment 1; KML targets point 5 in segment 2.

The pointer then leaves for the existing final frame/row-hover checks. Final screenshots qualify the stable route page, not the transient tooltip rectangle/placement; intermediate native evidence is the actual tooltip labels and hovered point position. Native coincident/missing/invalid samples and tooltip edge placement remain additional visual coverage. No dependencies changed. Prior dependency audit failures and the broader cohort transfer goal remain open.

The initial native timeout and pre-idle-input-correction gates are retained. The QA script repeated PointerMoved at the same location each frame, resetting egui's tooltip delay. It now emits one move and waits with a stationary pointer; the product delay, global deadline and expected data are unchanged. Both corrected native runs completed directly in fresh output directories.

Final validation: all six gates passed, full suite 3293 passed / 3 ignored. GPX/KML Source/Route plus actual tooltip-content workflows each passed 14/14 with zero effects. Independent verifier matched all six tooltip labels to source-verified point ownership, coordinates, elevation, timestamp and cumulative distance; prior time/elevation calculations and source/binary identities also pass.
