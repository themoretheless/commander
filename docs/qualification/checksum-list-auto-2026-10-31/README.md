# Automatic checksum-list format and algorithm detection — 2026-10-31

Extends the [Double Commander checksum-list verification workflow](https://doublecmd.github.io/doc/en/help.html), cohort #3, with tagged-record interoperability described by [GNU output modes](https://www.gnu.org/software/coreutils/manual/html_node/cksum-output-modes.html) and compact [OpenSSL record syntax](https://github.com/coreutils/coreutils/blob/master/src/cksum.c). Implementation is independent; no upstream application code is copied.

## Behavior

**Auto** is now the default in Verify checksum list. Recognized filenames (`MD5SUMS`, `SHA256SUMS`, `SHA384SUMS`, `SHA512SUMS`, `B3SUMS`, `BLAKE3SUMS`) and extensions (`md5/md5sum`, `sha256/sha256sum`, `sha384/sha384sum`, `sha512/sha512sum`, `b3/blake3`, `sfv/crc32`) select a format, case-insensitively. Every record must parse with that algorithm; a contradictory filename fails with an explicit override suggestion. A manual algorithm overrides filename hints, while actual record tags must still agree.

For unknown filenames, Auto accepts only a complete list that parses with exactly one supported algorithm. Untagged 64-digit hashes are ambiguous between SHA-256 and BLAKE3 and require manual selection or a recognized filename/tag. Ambiguous record layouts, unsupported tags, malformed records, empty lists and mixed algorithms fail before target hashing; no partially parsed rows are reported as verified. No algorithm is chosen by trying to find a digest that matches the file.

The existing GNU untagged/SFV formats remain supported. New tagged forms include `SHA256 (file name) = digest` and compact `SHA256(file name)= digest`, with MD5, SHA-256/384/512, BLAKE3 and CRC32 tags (and SHA-2 aliases). One algorithm per list is required. Names containing Unicode, spaces, parentheses and `) = ` are preserved by splitting at the last closing parenthesis. GNU leading-backslash filename escaping is decoded for tagged records too; literal SFV backslashes remain literal. Auto and explicit modes share the same parser and resolver.

Successful results identify the actual algorithm, including in copied report headings. An Auto setup error has an undetermined algorithm rather than claiming SHA-256. Changing Auto/manual selection clears stale results. The existing workload hash lane, cancellation, bounded regular UTF-8 manifest read, snapshot checks, within-folder resolver, symlink/traversal refusal and per-target verification remain owners. Limits remain 1 MiB / 10000 records. Auto may parse the bounded in-memory list against six formats; it performs no extra target reads before selection and no UI-thread file I/O.
