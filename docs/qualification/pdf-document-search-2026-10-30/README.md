# Whole-document PDF text search — 2026-10-30

Independent Rust extension of [ranger multi-page PDF text previews](https://github.com/ranger/ranger/blob/master/ranger/data/scope.sh), cohort #30. ranger's script extracts text from a bounded page range; Commander extends its existing native page text viewer with whole-document literal search and result navigation. This does not attribute this search UI to ranger or copy upstream implementation.

Search entire PDF expands a per-pane toolbar with literal query, Match case, progress and cancellation. The worker opens one PDFKit document from the existing validated source snapshot and scans one page at a time. Results retain only page numbers, bounded occurrence counts and the query snapshot, not document text. A virtualized result list opens the selected page's text and seeds its existing find toolbar with the same query/case policy. Literal matching uses the same Unicode simple-folding regex semantics as page find; metacharacters stay literal. Matching never spans page boundaries. Counts over 4096 per page are labelled 4096+.

The existing native workload/provider path, two-job admission cap, 64 MiB source limit, regular-file and before/after size/mtime checks, 30-second UI timeout and cancellation-on-drop remain. Search errors/cancellation/timeouts do not publish partial reports as complete or as no-match. Changing source/closing preview discards results and cancels the task; late channel completions cannot enter a replaced slot. Native objects remain on their worker; per-page autorelease pools release temporary native text after copying. Native extraction cannot be interrupted inside a single PDFKit call; a timed-out worker retains its admission permit until it returns.

Bounds: 4096 pages, 256 query characters, 256 KiB extracted text per page and 4096 retained occurrence count per page. Total document text is not concatenated or laid out. Every successful report scans all pages; errors on any page fail the report with the page number. Blank/image-only pages have no searchable text; there is no OCR. Locked/copy-restricted PDF policy is unchanged. Support is macOS-only, as with the existing native PDF viewer.

Five regressions cover literal metacharacters, Unicode/case counts, page-local boundaries, no-match, cancellation and failed-page nonpublication, query/page/text/count bounds, close/drop/late completion, and actual PDFKit search reaching page 2 of a two-page fixture. Full locked visual-qa suite **2704 passed, 0 failed, 3 ignored**. New native PdfSearch starts on image page 1, opens document search, enters Second page, requires the sole hit on page 2, opens it and requires text-page find to highlight exactly one match. The original PDF scenario remains separately qualified after the UI change.

This is text search, not OCR, semantic search, unrestricted PDF compatibility or a performance claim. Limits/reading order follow native extraction. Broader document/viewer parity remains open.
