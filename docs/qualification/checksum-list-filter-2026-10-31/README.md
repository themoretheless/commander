# Checksum-list result review — 2026-10-31

Adapts the [Double Commander error-focused log/review idea](https://doublecmd.github.io/doc/en/configuration.html), cohort #3, to Commander's checksum-list report. This is an independently implemented result projection; no upstream application implementation is copied.

## Behavior

Completed checksum rows can be viewed as All, Problems (mismatches plus errors), Mismatches, Errors or Matches. A case-insensitive literal filename search composes with that status choice; Clear search keeps the status filter. Queries are bounded to 256 characters. Matching uses the original manifest filename, including its relative components, not error messages or expected/actual digests. Outer query whitespace is trimmed for matching. Unicode matching uses Rust lowercase conversion, not locale-dependent collation or full Unicode case folding.

The view caches source row indices, including empty results, and retains original order and values. Publishing a new worker report invalidates it; preferences survive verification reruns and algorithm switches for the open dialog. Changing options/new reports resets the result scroll position. The full verification summary always remains visible, including cancelled/partial counts; a narrowed view is never presented as a successful verification of omitted or unprocessed records. An empty search result has an explicit message. Filter/search operate on retained records without filesystem reads or rehashing.

Copy verification report keeps its previous full-result scope and text format. New **Copy visible report (N)** copies only shown completed rows, with the actual algorithm, full verification summary, number shown versus completed, status filter and escaped query. Names/errors retain their escaped text representation and original expected/actual values. The copy function independently rebuilds the projection and rejects dirty/stale/corrupt indices before accessing records. A bounded formatting writer refuses output exceeding 1 MiB while writing; partial output is never copied. Empty views cannot be copied. This is a text report, not a new checksum manifest or a request to reverify only those files.
