# Export content-group reports

Independent continuation of cohort #96 [PeaZip archive analysis/task-log export](https://peazip.github.io/how-to-open-rar-tar-zip-files.html), adapted to Commander's clipboard port. The existing Copy check report and Copy check report JSON actions now include all retained SHA-256 content groups, including digest, checked group size, original ZIP indices, paths and member sizes. No new archive reads or dependencies are introduced.

JSON keeps commander.archive-check/v1 and its prior field meanings, adding content_comparison and content_groups. SHA-256 scans identify comparison as sha256_and_size; an empty group array means the completed scan found no matches, while null means comparison was not requested or no complete result exists. This is additive schema data, not a pairwise byte-comparison claim. Text appends explicit comparison/group/member sections. Report contents are the full retained scan, independent of current visible filtering or selected rows; recorded_at remains the UI result-recording time, not a new file verification.

Both formats share the existing aggregate 4 MiB bounded writer. JSON streams a borrowed serializable report instead of materializing/cloning groups into a JSON Value. Text JSON-quotes digests and paths, preserving Unicode and escaping LF/CR so names cannot inject fake lines. Archive and member paths require UTF-8; unsupported paths refuse explicitly. Oversize output fails without truncation or any clipboard update. The formatter accepts no password and serializes only explicit report metadata. Check errors and ordinary integrity reports retain unknown/unrequested comparison values.

Three new Rust regressions exercise exact original indices/path values, Unicode/control escaping, known-empty versus unrequested JSON, escaped output exceeding the aggregate bound and non-UTF-8 member refusal. Existing formatter regressions continue covering success/error metadata, captured strict mode, recording time and archive-path refusal.
