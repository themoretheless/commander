# DOCX and ODT text previews — 2026-10-30

Independent Rust adaptation of [Double Commander Office XML text-only viewing](https://doublecmd.github.io/doc/en/viewer.html), cohort #3. The upstream help describes Office package text without document formatting. Commander now supports DOCX and ODT body text; XLSX/ODS and page-layout fidelity remain open. No upstream code copied.

Preview routes these extensions through the existing cancellable text worker/cache, preserving listing/open-handle/path identity guards, latest-request ownership, debounce, timeout and retry. Packages allow 16 MiB compressed input, main XML 4 MiB, 4096 entries, 100000 XML nodes, nesting 128 and extracted UTF-8 text 256 KiB. Ordinary text keeps its original 256 KiB input limit and the shared output cache budget is unchanged. Package bytes are read in cancellable 32 KiB chunks; decompression and tree walking also check cancellation. XML parsing is bounded and runs on the worker. There is no disk extraction or external resource resolution.

Only word/document.xml or content.xml is opened. DOCX transitional and strict WordprocessingML namespaces are recognized independently of prefixes. Paragraphs, literal text runs, tabs and breaks are retained; deleted runs and field instructions are omitted. ODT paragraphs/headings, spans, explicit repeated spaces, tabs and line breaks are retained; annotations, tracked-change definitions and binary payloads are omitted. Table cell text uses tabs and row ends use newlines. XML entities are decoded by roxmltree with DTD support disabled. The existing transitive roxmltree 0.20 dependency is now direct; ZIP uses the existing dependency.

The preview labels the output text only; existing text sizing, wrap, find and copy controls operate on the extracted text. No images, styles, headers/footers, separate notes, document layout, macros or external relationships are rendered. Repeated table rows/cells are not expanded. Main XML must be UTF-8. Malformed, encrypted or unsupported packages report a typed document error. Text over the limit is rejected, not presented as a complete partial preview.

Four new regressions cover both packages' exact Unicode/paragraph/table output, namespace aliases and strict DOCX, entities and deleted content, ODT explicit spaces/breaks/annotations, invalid ZIP/XML/DTD, member/XML/output limits, cancellation and provider stamp changes. Native scenarios for each package require exact extracted text and one find match for message; they use minimal generated package fixtures, not an Office application's full document compatibility corpus.
