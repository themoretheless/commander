# Sort by captured inode

Independently adapts [eza inode sorting and inode display](https://github.com/eza-community/eza/blob/main/man/eza.1.md), cohort #79. No upstream implementation copied.

The command palette offers **Sort by inode**, toggling ascending/descending order with existing folder grouping, natural/case name ties, stable path ties, cursor and selection retention. The numeric key is inode first and device second; unknown identity remains last in either direction and known zero is valid. Two hard-link aliases with equal keys retain ascending name ties. This is listing-time lexical metadata; symlinks sort by their own identity without target following or new stat calls. Persisted view settings and listing JSON context retain the new sort enum.

In list view, the Inode header and values replace the active date column while inode order is selected. Logical sizes remain visible; Modified remains in accessibility metadata. Hover shows the full device/inode observation and marks a link's own identity. Icon view adds an Inode label. Selecting a date sort restores its normal date column. Inodes are scoped by device and may be reused; equal inode numbers on different devices are not treated as one object. Sorting neither selects aliases automatically nor computes reclaimable space.
