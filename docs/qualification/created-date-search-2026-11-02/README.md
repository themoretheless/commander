# Creation-time Find boundaries — 2026-11-02

Independent Commander extension of [eza separate creation-time metadata](https://github.com/eza-community/eza/blob/main/man/eza.1.md), cohort #79. The created-after:/created-before: grammar is Commander-specific; eza's source implementation is not copied.

Find/shared Query filters creation time independently of modification/access/status-change time. Strict UTC dates and RFC 3339 offsets/fractions reuse the existing absolute-date parser and saved-query validation across all name matching modes. Compiled predicates now name their timestamp field explicitly. Missing creation metadata is counted as skipped; no modification-time or archive-container fallback exists. New optional exact created_time cache records preserve signed epoch direction, seconds and nanos. Old/unsupported/corrupt records remain unknown. The metadata serialization budget includes the new worst-case field. Restored indexed observations require no source reads and can outlive deleted sources.

Find JSON adds nullable created_utc, retaining exact native instants and suppressing archive-container substitution. List filters and explanations use the same typed predicates. Existing after:/before: and accessed-after:/accessed-before: owners remain shared.

Regressions cover strict equality, offsets, fractions, pre-epoch values, unknown/invalid dates, saved-query round trips, exact/legacy/corrupt cached observations, live/indexed parity, unsupported birth times, stale deleted-source cache hits, archive unknowns and JSON creation values. New macOS-native created_search uses three real APFS birth observations with deliberately different future mtimes, tests an interval bounded by the first/last exact instants, an empty strict-before-first state, and a strict-after-middle state. Raw st_birthtime/st_birthtime_nsec facts are independent of the product helper. A neighboring accessed_search exercises shared date/provider behavior. Evidence and final hashes are retained here; native creation qualification is platform-specific, not a claim of birth-time support on every filesystem.
