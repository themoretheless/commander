# Empty file and directory search — 2026-10-28

Independent adaptation of fd `--type empty`, cohort repository #77 ([primary man page](https://github.com/sharkdp/fd/blob/master/doc/fd.1)). No upstream implementation copied.

`type:empty` matches lexical ordinary zero-byte files and directories with no entries. `type:empty type:folders` restricts it to directories; `type:empty type:regular` restricts it to ordinary files. `types:empty,socket` composes through the existing three-state OR list. Type conditions remain structural and independent of text mode/case. Symlinks, FIFO, sockets/devices and stored archive hard-link headers are not treated as zero-byte ordinary files. Native hard links are ordinary files. There is no recursive "contains only empty folders" interpretation: a directory with even an empty child directory is nonempty.

The shared lexical observation helper uses metadata length for files, rejects other native kinds, and examines at most the first directory entry without filtering it. Directory open/entry failures yield unknown. Normal live queries do not request the extra observation; empty queries do. The native index captures an optional is_empty fact on build, including one first-entry directory inspection; older snapshots remain readable but need rebuilding to establish this filter. It remains a build-time observation: a test changes a folder after building and verifies the old index retains its snapshot while live search changes. Existing 640-byte metadata accounting was increased to a conservative 704-byte bound, with the worst-case serialization regression passing. No benchmark or indexing-speed claim is made.

Archive ordinary files use their payload kind/size. Directory candidates wait until the archive inspection completes. A topology tracker records enclosing directories of all safe member paths before hidden/exclusion/depth presentation filters, so filtered children still establish nonemptiness. Leading ./ and redundant separators normalize lexically without filesystem canonicalization. Known children prove nonemptiness even after partial inspection. Otherwise empty requires a complete scan with no unsafe/unreadable/unsupported members, cancellation or member cap. Archive errors cannot prove empty directories. No member extraction occurs.

Topology and pending directory records share an 8-MiB accounting budget (path bytes plus conservative record overhead), in addition to existing archive member/content limits. If accounting fills, unresolved emptiness remains unknown and search reports truncation; candidates still reach other proven OR branches. This is a bounded metadata-accounting limit, not a measured process-memory ceiling. Directories already seen nonempty remain nonempty. Implicit archive folders are already nonempty by the existence of their descendants; explicit directory entries can qualify as empty.

Five new regressions cover canonical/saved type and list forms, lexical empty/nonempty files and folders, hidden children, failed directory reads, normalized/bounded/incomplete topology and safe partial results. The all-mode native/index/ZIP/TAR matrix uses actual files/directories/FIFO/socket, native hard/symbolic links, ZIP symlinks and TAR hard/symbolic-link headers, zero/nonzero payloads, late ./ children, child-directory occupancy, hidden/excluded children, depth, content conjunctions and archive scope. Legacy fact removal verifies skipped direct emptiness and retained known OR branches. A ZIP unsafe member prevents empty-directory proof while a safe zero-byte member still matches; a real visitor at its member cap leaves a candidate directory unknown.
