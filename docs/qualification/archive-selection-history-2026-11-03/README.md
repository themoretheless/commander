# Undo and redo archive member selection — 2026-11-03

Commander extension inspired by cohort #1 [Kiorg undo/redo](https://github.com/houqp/kiorg#key-features), scoped to in-memory archive member selection. Undo selection and Redo selection restore manual and bulk changes, including hidden members and results of per-group/global copy policies. Rules, filters, folder navigation and explicitly saved selection are not restored. No archive content or extracted file is changed by history traversal.

History belongs to the current immutable listing and resets on listing replacement/reopen, even for equal row counts. It retains at most 32 edits and 65,536 member IDs across the current snapshot and both stacks. Unrecordable/invalid selections reset history safely; shrinking back to a recordable selection establishes a new baseline. New edits discard Redo; no-op/refused actions and pending policy edits preserve it. Snapshots are created only when selected IDs change. Buttons expose their availability and have no keyboard shortcuts, preserving text editor shortcut ownership.

Two Rust regressions cover full-ID round trips, redo branching, no-op preservation, same-size replacement, step/total-ID bounds, oversized selections and invalid row IDs. Native coverage retains all mode/list/cutoff/candidate checkpoints and adds six real button checkpoints: Undo/Redo/Undo, a new group-selection branch, then Undo/Redo on that branch. Each verifies exact original member indices and unchanged pending policy fields. TAR and ZIP retain earlier integration and export regressions. verify.py independently checks every receipt, fixture, source/binary hash and native effect count.

Reproduce with run_checks.py, then prepare_capture.py and CUA launch separately for archive_protection_modes, archive_tar_content_groups and archive_content_groups, then verify.py. History is runtime-only; filesystem undo and wider native platform qualification are outside this transfer.
