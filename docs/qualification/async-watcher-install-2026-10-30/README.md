# Background watcher installation and retirement — 2026-10-30

Follow-up to the full-path folder-tab feature qualification. The general native FolderTabs run exposed synchronous initial PollWatcher subscription scanning on the UI thread during GoHome. This is an independently implemented responsiveness repair, not an upstream parity or throughput claim.

Mount profiling, path canonicalization, initial shallow polling scan and native subscription creation now run in a worker. The UI publishes a path/epoch binding immediately so directory listing can proceed independently. Installation notices carry backend metadata, never backend ownership. Completing a subscription and promoting polling to native each request reconciliation, covering changes before observation started. Existing callback binding epochs, bounded event inbox, event coalescing, deep-size invalidation and retry backoff remain in place.

The UI holds only a channel-sender lease. Navigation, suspension or replacement drops that lease without joining the worker. The worker retains actual watcher ownership and performs backend replacement/destruction there. Healthy native-policy paths start with shallow polling, then promote to the requested native depth; native promotion failure retains polling. Initial failure backs off. Panic after publication emits an epoch-bound backend error so a dead subscription cannot remain marked active.

Eight process-wide admission permits bound unfinished installations, including abandoned OS calls that have not returned. Healthy subscriptions release their install permit and wait for lease closure. An OS call cannot be forcibly cancelled; if all permits are occupied, later requests back off while the UI stays available. This bound covers installation work, not arbitrary OS teardown duration or the underlying notify backend's own threads. The change does not claim every filesystem operation elsewhere in Commander is asynchronous.

Five additional tests replace an immediate-start assumption with deterministic asynchronous contracts: a blocked installer runs on another thread, stays singleflight, returns control before release and keeps admission occupied after abandonment; completion reconciles an acknowledged initial snapshot; stale completion cannot activate a newer binding; failed initial install backs off while failed promotion retains polling; and a panic after publication retires the dead subscription. An actual filesystem regression waits for complete installation, acknowledges startup reconciliation, creates a child and requires a new observation ticket. Existing callback/gap/overflow/retry tests remain enabled.
