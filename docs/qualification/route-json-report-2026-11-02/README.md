# Copy parsed route JSON

Commander extension of the Strata-inspired route preview. Copy route JSON exports the current parsed GPX/KML Route through the existing deferred preview-text clipboard boundary. It does not reread a path, inspect the other pane or execute anything. Version 1 commander.route-preview includes source format, spherical distance model/Earth radius, no-interpolation gap policy, raw elevation model, total recorded distance, segment count, timing/elevation statistics and every parsed point.

Point indices are zero-based, segment numbers one-based. Each point preserves start-of-segment ownership, latitude/longitude, cumulative recorded distance, nullable recorded elevation, canonical RFC3339 timestamp or null and an invalid-time flag. Coverage counters and null statistics retain missing-versus-zero semantics. This is a derived Commander report, not original GPX/KML text, a route-import format or a replay/execution plan. The Source view remains the original-text view. Source paths/names are not added to the report.

Serialization streams into a bounded 1 MiB writer and refuses empty/non-finite/oversized models. Exceeding the limit returns an error without publishing a partial clipboard payload. The error remains visible for the same Route owner and is discarded on a different parsed source. Point count is bounded at 10,000. No dependencies changed.

Two regressions cover complete GPX/KML and single untimed-point reports, point/segment/nullable metadata/statistics, non-mutation, non-finite input and output/point bounds. Existing native GPX/KML Source/Route/hover scenarios now click Copy route JSON and retain the actual intercepted clipboard strings as route-report.json. Independent verification compares every field against the route snapshot already verified against source XML. QA uses owned fixture storage and a recording clipboard port, not the OS pasteboard. Source/binary hashes, launch receipts, reports, tooltip labels and frames are retained here. Prior audit failures and wider cohort parity remain open.

The initial build failure is retained in initial-failed: egui insert_temp returns a RawKey, so the error match arm needed an explicit statement block to match the success arm. Final gates use the corrected integration.

The pre-json-number-correction run is retained: its round-trip assertion compared serde_json's parsed f64 directly against an unparsed serde Value and observed a one-ULP difference in average speed. Expected values now cross the same serialization/JSON-decoding boundary before structural comparison. No production calculation, export precision, dependency feature or independent Python numeric assertion was changed. Final gates and captures use the corrected test source.

A later native GPX attempt terminated before the inspector checkpoint; its artifacts and pre-hover-click-spacing gates are retained. Installed egui's tooltip code suppresses hover moves within 100 ms after a click. The driver now waits at least 150 ms after the mode-switch click before its one hover move, keeping the same tooltip delay, overall deadline and data assertions. This removes that interaction race; no claim is made that host scheduling can never stall.

Final validation: all six gates passed (build, full tests, strict Clippy, check, format and diff); 3295 tests passed / 3 ignored. Final native GPX and KML scenes each passed 14/14, with exactly one recorded clipboard call and zero other native effects. verify.py passed source/executable hashes, independent XML geometry/timing/elevation calculations, tooltip labels and exact exported point/statistic comparison. Both final stable frames were visually inspected: the copy button and complete route/elevation views are visible. Transient tooltip placement and the OS pasteboard remain outside this qualification.
