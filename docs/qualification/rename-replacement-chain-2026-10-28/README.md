# Sequential batch-rename replacement pairs — 2026-10-28

Independent adaptation of multiple Find/Replace pairs from [Double Commander Multi-Rename](https://doublecmd.github.io/doc/en/multirename.html#multirename_multiplepairs), cohort repository #3. The documented multiple-pair feature inspired the UI; Commander defines explicit sequential semantics and separate rows, without copying upstream implementation or claiming identical pipe-list behavior. The initial swap-case candidate was not confirmed in that source and was not implemented.

Add replacement appends up to sixteen extra pairs after the existing primary pair. Each pair sees the previous result, and all share regex/ignore-case/first-only options and the chosen whole-name/stem/extension scope. The chain runs before case, prefix/suffix, numbering and final cleanup/normalization/length transforms. Directories still have no extension target. Remove deletes a row, Reset clears the chain, and presets retain its order. Empty extra Find values, invalid regexes, more than sixteen pairs or over 64 KiB combined extra-pair text block application. Existing single-pair behavior and default serialized rules remain compatible; the new vector is omitted when empty. Presets also retain their existing 4096-byte per-field bounds for every extra field.

Matchers compile once per batch. Chained replacement output is capped at 64 KiB at each stage, while later pairs may shrink a permitted intermediate back into a valid filesystem name. Literal replacements never interpret dollar captures; regex replacements retain exact capture-reference grammar. The already-locked regex-automata 0.4.18 package was promoted to a direct dependency to reuse its interpolation parser with bounded capture appends; no package version upgrades were introduced. Scratch capture interpolation accounts for literal replacement bytes plus checked capture bytes, so an expanding chain cannot allocate an unbounded replacement before its output check. Original single-pair replacement continues through its existing path.

Expansion-limit rows retain their original name for preview and receive a distinct blocking status/reason. Both the UI submit gate and real workspace application reject the entire batch before any rename if even one row exceeds the limit. This is tested with another independently valid row, preventing partial application. The planner keeps one target string per row rather than cloning successful result strings into a second result collection.

Six new regressions cover sequential order, first-only behavior, independent case/extensions/counter composition, directory handling, scoped replacements, regex compatibility (named/numbered/missing references, dollar escaping and zero-width matches), literal casefolded replacement, saved/default JSON, pair/text/regex bounds and exact 64-KiB intermediates that subsequently shrink. Cached-preview tests cover editing/removing a pair and invalid submit blocking; preset tests cover persistence and per-field bounds. Real workspace acceptance checks preserve bytes, Undo/Redo, collision refusal and whole-batch rejection on a mixed expansion limit. The initial expansion-bound fixture used $1$1x, whose second reference greedily means 1x; it was corrected to ${1}${1}x before final qualification, matching the same engine grammar checked by the compatibility tests.

Final full suite: **2613 passed, 0 failed, 3 ignored** with `cargo test --locked --features visual-qa`. All-target Clippy with warnings denied passed. Native RenameOptions now retains the earlier option/reset/normalization checks, then adds two actual UI rows and types TXT→Doc and Doc→Final; readiness requires those rows, Final.txt in the preview and the original fixture file unchanged. Capture evidence follows below. No commit or push. The overall 99-repository transfer objective remains open.
