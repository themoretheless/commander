# Rename and duplicate saved workspace profiles

Continuation of the Krusader-inspired [profile tab sets](../profile-tab-sets-2026-11-02/README.md), implemented independently. The profile-name field now supplies Rename selected and Duplicate selected, alongside existing capture/replace/apply commands.

Rename changes only the selected saved record's name and retains its position. Duplicate appends a copy of the selected saved record under the new name. Neither recaptures current panels or applies/navigation-mutates the profile. All roots, filters, policies, trusted-template metadata and tab-layout data remain unchanged as JSON values apart from name. Duplicate and rename conflicts refuse without overwriting; a same-name rename is a no-op without another disk generation. Existing name/layout/size limits and stale-editor atomic commit checks apply. Failed commits keep selection and the previous editor book.

Two new tests cover all-field preservation, full layouts, explicit collision refusal, invalid names, no-op disk preservation, atomic reopen and stale-rename refusal with retained selection. Native profile_names seeds a saved Work profile with two left tabs, Saved branch title and *.rs filter, then retargets current panels to different folders. Actual text/key/pointer events rename Work -> Project, duplicate Project -> Copy, then attempt Copy -> Project. Recorded on-disk generations must be 1 -> 2 -> 3 -> 3 and the conflicting attempt must retain both profiles and Copy selection. Current roots must stay unchanged. This directly distinguishes duplication from capturing current panels.

The prior full-tab profile Apply scene is the control. All filesystem writes use QA's existing temporary storage-root override. No physical OS input or process-restart qualification is claimed. No dependencies changed; previous dependency audit failures and the full 99-repository transfer goal remain open.

Validation: all six gates passed (build, full tests: 3,269 passed / 3 ignored, strict Clippy, ordinary check, formatting and diff whitespace). Final rename/copy/conflict native workflow passed 16/16; prior full-tab restore control passed 14/14. Independent verification matched unchanged saved fields, disk generations 1/2/3/3, a byte-identical store on name collision, retained Copy selection and unchanged current roots. Both final screenshots were visually inspected and all native effect counters are zero. Both scenarios are in CI; final captures are selected by native-launch.json and profile_tabs-launch.json.

The control exposed a real layout issue after the new button row: Apply/Close could fall below the visible scrolling body. They now occupy a separate footer and the window has a wider initial size. Earlier incomplete captures are preserved. The control only retries an uncommitted Save when the named record is absent and no error is present; deadlines are unchanged. Native maximum-size lists, stale-rename UI feedback and process restart remain additional coverage work.
