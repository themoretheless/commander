# Native sync profile loading and side swap

Continuation of the Krusader-inspired synchronizer workflow. The existing CI sync_review scene now saves Work after deliberately skipping notes.md, clicks Swap comparison sides, checks the opposite root pair with a fresh stamp and notes.md ToLeft, then clicks Load and compare. Loading Work restores the original roots and creates a fresh stamped plan with notes.md ToRight. The old Skip edit and review ordering/query are discarded, while the saved profile remains unchanged. It then renames and deletes the profile, collapses the section and copies the rebuilt plan. Every action is driven through pointer/key events; the fixture roots and comparison model are not rewritten by QA code to simulate swapping/loading.

Snapshots at comparison phases 94 and 97 retain actual roots/stamps/default directions and reset acknowledgement/review state. Final rows must equal the initial comparator baseline, not the earlier edited plan. The target notes.md must remain absent. The five previous exports plus the final rebuilt report use the recording clipboard port; no Apply/Sync action is invoked. The neighboring byte-comparison scene remains the control. QA storage is isolated to the owned temporary fixture.

This UI scenario uses TwoWay and the fixture hidden-file settings. Mirror-policy inversion, explicit large-plan acknowledgement invalidation, live custom guard preservation and non-default comparison settings are covered by existing model regressions, not claimed as separate native coverage here. Profile replacement/collisions, process restart, corrupt storage recovery and OS clipboard integration remain additional coverage. No dependency changes; previous dependency audit failures and broader cohort parity remain open.

Host-run caveat: the first content-control instance (PID 1758) remained live in the AppKit event loop during inspection; its stack sample is retained. It terminated before the subsequent activation action, and CUA relaunched the wrapper into the same output directory (final fixture PID 1922). The final completed control artifacts pass all content/report/effect assertions and use the recorded identical binary, but this is not proof that the original process resumed or that this control is reliable unattended. The primary swap/load run completed directly in its own output directory. No deadline or expected-result assertion was relaxed.

Final validation: all six gates passed, full suite 3281 passed / 3 ignored. Primary swap/load workflow and completed content control each passed 15/15; independent verifier passed exact swapped/restored roots and stamps, fresh default row actions, profile management, report metadata, content results, effects and source/binary identities. Both final frames were visually inspected. Six/two recording clipboard calls are the only native effects.
