# Hex viewer session bookmarks — 2026-10-30

Independent Rust adaptation of [Midnight Commander viewer marks](https://github.com/MidnightCommander/mc/blob/master/src/viewer/actions_cmd.c), cohort repository #40. Its public command handlers save and restore the selected marker's display-start position. Inspected through the GitHub connector; no upstream implementation copied.

Commander offers ten numbered slots inside each open hex viewer. Set here stores the exact current page offset, Jump uses the existing asynchronous bounded read, and Clear empties the selected slot. The dropdown lists slot numbers and saved hexadecimal offsets. Slots are independent and may be overwritten, including with unaligned offsets or EOF. They are session-only and never shared across viewers or persisted; Reload clears all ten when accepting a fresh file version. Buttons are disabled during a read. Missing or failed pages cannot be saved. Jump retains expected file identity/size/change validation, so a changed file cannot silently use stale bookmarks.

Two regressions cover all ten slots, independent overwrite, EOF, viewer isolation, in-flight and failed save rejection, actual byte restoration, changed-file rejection and Reload clearing all slots while accepting the new content. The native HexPreview scenario retains its existing page/absolute/percentage/decimal interactions, then sets slot 1 at zero, visits page 4096, jumps back to zero and clears the slot. Intermediate readiness checks require the saved mark and exact positions; final phase 53 requires an empty slot and decimal display at zero. No full upstream viewer parity is claimed.
