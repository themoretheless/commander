# Bounded XZ inside ZIP/ZIPX

Independent integration of PeaZip cohort #96 XZ ZIP support:
https://peazip.github.io/zip-files-utility.html
https://peazip.github.io/zipx-file-format.html

ZIP method 95 now uses the already-present xz2/liblzma stream decoder with a 64 MiB memory budget. No Cargo dependencies or versions change. The shared zip_reader bounded variant now covers both ZIP LZMA and XZ, retaining metadata delegation, exact declared-size checks and ZIP CRC at EOF. LZMA retains its cached validated properties and EOS rules. Standard codecs still use zip-rs through immutable metadata dispatch.

XZ decoding validates the XZ stream's own checks and supports concatenated streams and legal four-byte-aligned Stream Padding. The decoder enforces the memory budget for every block and subsequent stream, rather than inspecting only an initial header. Encrypted members fail before decoding. ZIP CRC remains mandatory even when the XZ stream uses CHECK_NONE. Archive listing, content search, integrity checking and regular/symlink extraction share the adapter. Existing byte budgets, cancellation, traversal protection, no-clobber extraction and partial-file cleanup remain in place.

Independent Python lzma/xz CLI producers create ZIP method-95 fixtures with CRC32, CRC64, SHA-256 and no internal XZ check, Unicode/empty members, concatenation/padding, forged 4 GiB dictionary requests in initial/later blocks and a later stream, bad ZIP CRC/size, truncated/trailing data, corrupt XZ check, encrypted flag, ratio bombs, unsafe names and safe/escaping symlinks. Forged dictionary block headers have their header CRC recomputed: the independent decoder explicitly reports a memory-limit refusal, not merely malformed metadata. verify_fixtures.py checks hashes/ZIP metadata and decodes through xz with the same stated memory budget, plus per-stream Python/liblzma decoding. Python's convenience decompressor stopped at padding between concatenated streams; the verifier now explicitly validates and consumes aligned padding between individual stream decoders, while the xz CLI remains the aggregate byte oracle.

Six new Rust regressions exercise exact payloads, decoded sizes, extraction/repeated-extraction preservation, all invalid/refusal fixtures, ratio/path/cancellation safeguards, symlinks, live/indexed ZIP/uppercase-ZIPX content search and decoded-byte integrity limits. The full suite also retains prior LZMA header-mutation/EOS/memory checks and standard ZIP codec regressions.

Native ArchiveMetadata extends from 21 to 24 pointer phases and adds g-xz.txt, raw-copied from the independent producer. Seven fixed metadata states require all eight actual rendered fields visible. A fresh per-frame list of rendered row rectangles and the real inner scroll clip let the driver wheel the virtualized member list to a not-yet-rendered row, then click it; it also scrolls the outer sheet for details. It never sets member focus, selection or scroll state directly. verify.py checks exact labels/values, common native gates, effect isolation and final binary hashes. Native capture qualifies display and actual scrolling; extraction is qualified by Rust integration fixtures. Other ZIPX codecs, ZIP-based document routing, creation and passwords remain open.
