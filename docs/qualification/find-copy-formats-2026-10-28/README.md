# Find clipboard formats — 2026-10-28

Independent adaptation of Nimble Commander's [Copy Item Name/Path and terminal-oriented filename actions](https://github.com/mikekazakov/nimble-commander/blob/main/Docs/Help.md). Commander exposes formats within Find and reuses its owned clipboard quoting/formatting; no upstream code copied and no claim of identical upstream controls.

Copy as offers Full paths (the unchanged default), Names and Shell arguments for both all-visible and selected-visible result copying. Output follows displayed/time order and respects hiding/selection. Paths keep full virtual archive member paths; Names copy final components. These two formats retain existing one-result-per-line control escaping. Shell arguments instead quote each real native reveal path with the existing POSIX single-quote encoder and join arguments with spaces. Archive hits use their real archive-container paths in this format, with one argument per result, including repeats. Embedded newlines remain inside quotes rather than being changed into different filenames. Nothing is executed by copying. Clipboard feedback names the chosen format; the choice lives only in the current Find instance.

This is text export with the existing lossy UTF-8 path conversion for non-UTF-8 names, not a raw-byte argument transport. Shell output supplies arguments, not a command or an archive-member extraction operation.

The focused regression covers names with apostrophes, command-substitution-looking text and an embedded newline, hidden rows, selected/all scopes, default path compatibility and archive container mapping. A real /bin/sh parser receives the generated arguments via set/printf and must return exactly the original controlled argument bytes with NUL separators, proving quoting and argument boundaries rather than only matching a golden string.
