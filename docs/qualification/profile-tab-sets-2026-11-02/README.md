# Complete tab sets in workspace profiles

[Krusader panel profiles](https://docs.kde.org/trunk_kf6/en/krusader/krusader/profiles.html) retain all tab paths, each active tab and the active panel. This milestone extends Commander's named profiles to those same core owners, independently and without krusaderrc compatibility.

New named/default captures include both open-tab sets, active tab indices, active side, tab names, close protection, full-path labels, view configurations and Miller widths. Top-level filters still belong to each active panel; inactive-tab filter/history/cursor/selection state is not captured. Selection snapshots and closed-tab history are excluded from the profile. Current closed-tab history is retained on application. Apply replaces the open tabs; the dialog previews every path and active indices, with scrolling for long sets. Protected current tabs refuse replacement. A refused application keeps the window open with feedback.

A versioned optional tab_layout field preserves old store readability. Null/missing layout uses the previous current-folder behavior and preserves background tabs. New layouts need 1–8 absolute-path tabs per panel, consistent root/active indices, known fields and version 1, bounded to 512 KiB; the existing 4 MiB store gate still applies. Invalid layouts refuse the entire application before tabs/policies change. Unsupported native tab-path JSON serialization is refused at capture. Missing directories in full sets remain represented by their saved paths and the normal listing error; legacy profiles retain the previous missing-side behavior. User protection flags in captured tabs restore normally after admission.

Three new regressions cover complete state restoration, active side/indices, view/name preservation, excluded selection metadata, corruption/protection refusal, atomic store reopen and bounded format checks. Existing legacy and named profile regressions remain. Default save/apply commands now use complete sets; the legacy developer capture helper remains compatible.

Native profile_tabs starts with two tabs on each side, second active tabs, active Right panel, an Icons background tab and Project title. It saves through the dialog, then fixture setup closes extra tabs and retargets the panels. Actual Apply restores the full saved set. The actual disk envelope and final runtime sets/active side/closed history are recorded. The prior named-profile create/replace/apply scene is the control. The existing QA storage-root override isolates every write. This is egui event injection, not process restart or physical-input qualification.

Validation: all six gates passed (build, full tests: 3,267 passed / 3 ignored, strict Clippy, ordinary check, formatting and diff whitespace). Native full-tab-set and prior named-profile workflows each passed 14/14 with zero native effects. Independent verification matched every saved/runtime tab entry, both active indices, active side, background Icons mode, Project title and retained closed histories. Source/binary/tool hashes agree; both final screenshots were visually inspected. Final capture records are native-launch.json and workspace_profiles-launch.json. The first full-tab attempt is retained: a fixture name mismatch prevented advancement; it was corrected without changing deadlines. Both scenarios are in CI.

Native protected-tab refusal, malformed-profile feedback, eight-tab scrolling, default-profile command routing and process-level restart remain dedicated coverage work. Core admission/store behavior and protection are tested; no cross-platform runtime qualification is claimed.

No dependency changes. Existing dependency-audit failures and the broader 99-repository goal remain open.
