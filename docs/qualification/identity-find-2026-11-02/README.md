# Recursive identity-based Find

Independently adapts [rmlint's hard-link identity distinction and same-file search workflow](https://github.com/sahib/rmlint/blob/master/docs/rmlint.1.rst), cohort #86. No upstream implementation copied.

**Find hard-link aliases of cursor** opens and runs normal recursive Find for the highlighted regular file, including that file and its aliases within the source pane's folder tree. It captures the original root and complete device/inode pair in a typed modal request before dispatch, so another panel becoming active cannot redirect the request. Unlike visible-group selection, this command needs no visible peer. Directories, symlinks and incomplete/unavailable cursor identities cannot start it. The generated query is `device:D inode:N type:regular archives:off`; usual root validation and search bounds/exclusions remain active.

The composable numeric fields `device:` and `inode:` accept exact unsigned decimal IDs, including zero/full-width values, and optional leading `!` exclusions. Repeated filters combine through AND; Exact/Fuzzy/Regex modes do not reinterpret numbers. Saved queries and serialized expressions retain the predicates. Explanations report the observed component. An inode alone is not globally unique; combine it with device to describe a filesystem object. Identity reuse and stale observations remain possible, and results do not authorize a filesystem operation.

Live providers use already obtained lexical Unix metadata. Indexed providers use existing optional volume/file_id fields independently; no index schema widening or fabricated FileEntry operation identity is introduced. Metadata-only indexed matches need no source-file reread, even after deletion. Missing components count as skipped even for exclusions. Archive members have no native device/inode observations and are explicitly skipped when archive search is enabled; container identities and archive header device fields are not substituted. No account lookup, hashing or reference-file stat is added by the new predicates. The command starts with archives off, and users may edit the query or change root through normal Find controls.

## Validation

Three regressions cover grammar/mode/expression/serde round trips and rejected nondecimal/overflow values; real recursive hard links, copies and links across live and serialized-index providers in every mode with content conjunctions, unknown archive IDs, zero/full-width cached IDs, independent missing components, genuinely absent old JSON fields and retained matches after source removal; and command eligibility without a visible peer plus root/identity binding across panel changes. Existing modal coalescing coverage includes the typed identity request.

Native identity_find runs the palette command with an alias in a nested folder, checks two regular-file hits with no skips, then edits the real Find query to turn archives on and verifies one explicitly skipped archive member. Independently captured raw device/inode facts and explanations form the verifier's reference. Existing hardlink_selection is the neighboring native regression. Source, binary and external checksum-oracle hashes bind final acceptance. Native Windows identity discovery and aliases outside the chosen search tree are not established.

The independent samefile-reference.json records `/usr/bin/find -type f -samefile ... -print0` on an equivalent temporary fixture, its exact command, executable hash and the two resulting relative paths. This verifies the same-file workflow recommended in rmlint documentation separately from Commander. Numeric device filters select results; they do not prune traversal or replace the existing search-root/exclusion policy.

Final validation: all six checks passed; **3153 tests passed / 3 ignored**. Native identity_find passed **16/16** with zero external effects; neighboring hardlink_selection passed **14/14** with exactly one intercepted clipboard write and all other effects zero. Both runs use the same final source-bound binary. Independent raw identity facts matched both result paths and numeric explanations; the command source label was Live (archives off), then Live + archives after editor activation, with skipped counts 0 and 1 respectively. The independent samefile reference and final source/binary/oracle hashes passed verification, and both final frames were inspected. Ordinary non-QA check retains the pre-existing unused-response warning in diff_find.rs. Full parity with the 99 repositories remains open.
