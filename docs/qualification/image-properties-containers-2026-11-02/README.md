# Header properties and EXIF container qualification

Continuation of the independently implemented Strata-inspired image metadata inspector. Get Info now shows actual container Format and Header dimensions for JPEG, PNG, classic TIFF and WebP, including files without EXIF. Valid header properties survive broken/unsupported EXIF with a separate explanatory note. The group is titled Image metadata. Header dimensions describe the encoded primary image/canvas before orientation, not an assertion that the full raster stream is valid or a replacement for the separately stored EXIF pixel dimensions.

The Rust header reader uses checked slices/offsets and no raster decoder or pixel allocation: PNG IHDR with CRC validation, JPEG SOF markers, classic little/big-endian TIFF primary IFD and WebP VP8/VP8L/VP8X. Format details were checked against [PNG IHDR](https://www.w3.org/TR/png-3/#11IHDR), [WebP RIFF](https://developers.google.com/speed/webp/docs/riff_container) and [WebP lossless headers](https://developers.google.com/speed/webp/docs/webp_lossless_bitstream_specification). Existing regular-file identity fences, no-follow Unix opens, two-worker cap, cooperative cancellation, ten-second UI timeout and first-2-MiB read limit remain.

Seven focused metadata tests pass. Real JPEG/PNG/TIFF/WebP files with and without EXIF are independently raster-decoded as 4×3 in tests, then read through the filesystem metadata worker. Synthetic cases cover large dimensions without pixel allocation, bad PNG IHDR CRC, valid raster with corrupt EXIF, big-endian TIFF headers, lossy WebP headers and malformed offsets. A valid JPEG with EXIF placed after the prefix parses with the full in-memory oracle but the production worker cannot reach it, proving the read-limit boundary. Original stale-file/link/cancellation and late-result owner regressions remain.

Full result: **3224 passed / 3 ignored**, all six build/test/static gates passed. Five native window scenes (JPEG/PNG/TIFF/WebP with EXIF and PNG without EXIF) each passed **14/14**, all external-effect counters zero. All five frames were inspected. The header-only PNG visibly shows PNG, 4 × 3 pixels and No EXIF metadata found; EXIF scenes scroll until GPS altitude is fully visible. These are injected app events in a native window, not physical OS input qualification.

`verify.py` uses Python standard-library JPEG markers, PNG chunks/CRCs, TIFF IFDs and WebP RIFF parsing to derive the captured values independently. It matches all 16 properties in each EXIF scene and the two properties/absence note in plain PNG, proves identical raw EXIF payloads across four containers, checks clip geometry, manifests, PNG dimensions, zero-effect counters and final source/binary/core/validator hashes. Facts are in `independent-container-facts.json`.

Final capture directories under `native-captures`: `1793600779009245000/exif_png_info`, `1793600822678941000/image_header_info`, `1793601203229360000/exif_tiff_info`, `1793601245728390000/exif_webp_info`, `1793601282065658000/exif_info`. No dependencies or deny rules were changed.
