# Duplicate scan subfolder levels — 2026-10-31

Independent Rust adaptation of the [fclones recursion-depth option](https://github.com/pkolaczk/fclones/blob/main/fclones/README.md#finding-files), cohort #85. Commander deliberately labels the setting as **Subfolder levels**: 0 enumerates only files in the root, 1 includes files in its immediate subfolders, 2 also includes the next level, and empty means unlimited. This differs from fclones' CLI file-depth numbering, where `--depth 1` keeps only root files; no CLI compatibility is claimed.

With **Include subfolders** active, **Apply depth** validates a staged unsigned decimal value (up to u32::MAX, at most ten digits) and restarts the current recursive scope. Draft edits alone leave the current groups and applied depth unchanged. Invalid input disables Apply and shows an error; the caption continues to show the actual applied bound. **Reset depth** restores unlimited depth. Turning recursion off keeps the depth preference/draft for later activation and uses the existing listing scope; turning it on enumerates the retained root with its applied bound. Other scan preferences survive, while manual group choices are rebuilt as with existing rescans. Preferences last for this tool opening, not across app restart.

The iterative worker carries each directory's level alongside its path and checks the bound before queueing any subdirectory. Root files use level zero. Skipped descendants are not enumerated or hashed, and intentional depth pruning does not count as an unreadable/partial scan. Metadata for directory entries in visited folders is still observed. Existing cancellation, hidden-folder inclusion, no-follow symlink behavior, physical-identity collapse, size/name filters, full hash verification and removal/report owners remain. This does not implement path exclusion, multiple roots, alternate link policies or performance parity with fclones.
