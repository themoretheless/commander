# Find regular files by observed hard-link count

Independently adapts [rmlint hard-link inventory/count handling](https://github.com/sahib/rmlint/blob/master/docs/rmlint.1.rst), cohort #86, into Commander's Find. The `links:` query grammar is Commander's own; no upstream implementation copied. POSIX find -links is an independent validation reference, not a claimed additional cohort repository.

`links:>1` finds regular files with multiple observed directory links, without needing a cursor-file identity. `links:2` / `links:=2` are exact, `links:2..4` is inclusive, and `<`, `<=`, `>=`, `>` retain exact unsigned 64-bit arithmetic. Impossible strict boundaries, negative/fractional/unit-valued/overflowed inputs and reversed ranges are rejected. Conditions combine through AND across Exact/Fuzzy/Regex modes and survive canonical expression, chips and saved-definition JSON round trips.

Live scans reuse lexical listing metadata. Count is the filesystem observation, including aliases outside the search root; it is not the number of result rows or a reclaimable-storage estimate. Directories, symbolic links and other known non-regular kinds are excluded. Missing regular-file counts stay skipped, including archive payloads; the container's count is never borrowed. Known zero remains distinct from unknown. Explanations display the observed count, and additive nullable `hard_links` in Find JSON preserves exact integers.

The existing content index stores an optional observed regular-file count and restores it only with consistent regular/non-link flags. Old/missing/unsupported or contradictory records remain unknown. Cached counts remain snapshot facts after source changes/removal; operation identities are not fabricated and no live stat is performed to re-evaluate them. Rebuild the index to refresh observations. Windows counts remain unsupported/unknown; there is no account lookup or new runtime dependency.
