# Disk usage file-count metric — 2026-11-02

Independent adaptation of [dust file counting including duplicate inodes (-f -s)](https://github.com/bootandy/dust/blob/master/README.md), cohort #82. No upstream implementation copied.

Disk usage adds File count alongside Logical size and File allocation. File count weights each successfully observed non-directory path as one, including empty files, symbolic links, special entries and separate hard-link aliases. Directories aggregate descendants and do not count themselves. It is an entry count, not a unique-inode inventory. Same-device traversal, no directory-symlink following, cancellation and inaccessible-path warnings remain shared. Changing the metric scans the captured original root afresh, so the bounded map selects by count rather than reusing a byte-ranked subset.

UI values use exact integer entries, including explicit incomplete/overflow indicators. Tree/filter/share and Map consume the selected snapshot. JSON adds measurement_unit, known_value and nullable file_count. For count snapshots logical_bytes, file_allocation_bytes and known_bytes are null; unavailable/cancelled full file_count values are null while known_value retains the observed subtotal. CSV retains the existing first 21 columns and appends measurement_unit, known_value and file_count (24 total); byte fields are blank for counts. Legacy byte-mode values remain numeric, count-only fields null/blank. Consumers requiring exact CSV headers must accept the added fields.

Regressions cover empty-file ranking, hard-link aliases, symbolic links, count-versus-byte rank reversal, exact u64 display, unavailable totals, and truthful JSON/CSV units. Existing loss-aware aggregation tests continue covering overflow/cancellation. New CI scene disk_count drives both metric changes, Tree/Map, JSON/CSV copies and captured-root rescans after listing navigation. Raw independent Unix path, device/inode and block observations are preserved for Python verification. Neighboring disk_allocation and disk_usage_export scenes run on the same binary. Checks, screenshots and final hash binding are recorded in this bundle.
