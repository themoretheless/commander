# Text diff difference-block navigation — 2026-10-31

Independently adapts [Double Commander Compare by Contents difference navigation](https://doublecmd.github.io/doc/en/help.html#cm_CompareContents), cohort #3, to Commander's read-only unified diff. It does not add editing, merging or patch application; no upstream implementation is copied.

Contiguous Insert/Delete rows form one difference block, separated by Equal rows. The immutable diff's block index is built once when opened. The first block is initially selected/revealed. **First difference**, **Previous difference**, **Next difference**, and **Last difference** move among blocks and reveal their original row positions. Previous/Next stop at the ends; First/Last remain available to recenter after manual scrolling. The selected block has a neutral hover-color background, preserving inserted/deleted text contrast. A position label shows selected block/total and 1-based source line positions/ranges for the **− file** and **+ file** operands, matching the header's explicit signs rather than physical pane position. Pure insertion/deletion sides report a before-line anchor.

Clicking navigation takes the existing diff keyboard owner. Exact **Alt+Up/Down** navigate previous/next, **Alt+Home/End** first/last; extra modifiers do not match. Existing **Tab/Esc** returns keyboard control to files. Modal/text-input routes outside the navigation widgets retain ownership; open popups do not dispatch diff navigation. Ordinary diff scrolling stays with its existing owner, now using measured viewport height for page steps. The viewport reserves room for the new controls and Close within available height.

The existing bounded file reads, UTF-8/regular-file checks, LCS cell cap and retained source/edit-script semantics are unchanged. This navigation does no I/O, does not change source text and does not rebuild the diff while stepping. Virtualized unwrapped row rendering continues to lay out only the viewport plus its existing overscan. End-of-line markers remain part of the existing diff's change script.

The first green run/capture before a visual correction is preserved under `before-contrast-fix/`. Frame inspection caught inserted text merging into the original selected background and unsupported arrow glyphs in the key hint; final source uses a contrasting neutral background and ASCII Up/Down. Physical pane positions are also disambiguated with explicit −/+ operand labels.

A subsequent capture exposed a fixture publication race: rows were present while named-child cursor placement was still deferred. The final QA opener waits for the actual cursor and expected diff-target pair, then confirms the tool exists before marking it opened. The failed attempt and its green source checks are retained in `before-fixture-publication-fix/`. This changes fixture dispatch readiness, not production target selection or file-read behavior.
