# Duplicate JSON report — 2026-10-31

Independent adaptation of [fclones machine-readable reports](https://github.com/pkolaczk/fclones/blob/main/fclones/README.md), cohort #85. Commander now offers **Copy JSON report** alongside the existing CSV proposal. This is a Commander schema (`commander_duplicate_report`, version 1), not fclones import/replay compatibility.

The report describes the retained scan and current proposal: applied root/scope, listing-versus-recursive metadata source, effective/configured depth, size bounds, basename rules, minimum copy count, selected keeper policy, view sort, scan issues/partial status, group/file totals and proposed Trash totals. Groups follow current view order and retain their original one-based group IDs; members retain original order and explicit keep/trash/skip actions. Policy labels provide context, while per-member actions capture manual overrides. Inactive configured depth is separate from the effective recursive depth. Unapplied name/depth/size/minimum drafts are omitted.

CSV and JSON share the same safe action and complete-group-permutation validators. Missing or invalid keeper indices skip the affected group; report actions cannot invent removal targets. Both report formats remain read-only, with existing clipboard ownership and errors through the existing toast path. JSON export performs no file metadata/content reads and does not recompute hashes; it is a saved scan-time proposal, not a current-filesystem certificate or an executable removal plan. The retained 64-bit digest prefix is deliberately not exported as though it were a full content hash.

Serialization streams through a 1 MiB bounded writer, so it fails atomically instead of copying a truncated prefix or first constructing an unbounded JSON DOM. Paths must be lossless absolute UTF-8 without NUL, with ordinary JSON escaping for quotes, newlines and other characters. Busy scans, no records, invalid group order, unrepresentable paths and over-limit reports return errors without a clipboard write. Partial completed scans may export their verified groups with an explicit issue count/partial flag; omitted/unreadable files are not asserted absent.

Two new regressions compare JSON records with parsed CSV and authoritative totals, verify exact special-character paths, sorted/original IDs, applied settings, partial status, draft independence and invalid-keeper skipping; they also cover invalid order/root/member paths, non-UTF8, busy/empty state and oversized Unicode output. The existing controls test now clicks the JSON button. A native scene sorts groups, copies the proposal, keeps all groups and copies the skipped proposal, reapplies the policy and copies the restored proposal. It is included in CI and the stable registry.
