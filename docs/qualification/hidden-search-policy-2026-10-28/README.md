No upstream code copied. Unlike ripgrep's default, Commander preserves its existing hidden-inclusive search behavior unless the query requests another policy. The Only result filter is Commander's additional adaptation.

hidden:include / hidden:exclude / hidden:only classify dot-prefixed components below the explicitly chosen root. Include/on/true and exclude/off/false are equivalent spellings; case-insensitive option parsing, repeated identical controls and saved expressions/JSON are supported. Conflicting policies are rejected. Structural hidden values do not influence case:smart. An explicitly chosen dot-hidden root stays searchable and does not label all its visible children hidden. Classification is lexical dot-name policy, not Finder/Windows hidden metadata or symlink-target visibility, and is independent of pane Show hidden.

Exclude removes native dot entries before traversal, filters cached native paths before text/archive inspection, and filters hidden archive member paths. Only does not prune visible directories or archives: it still finds hidden descendants and members. Shared metadata matching classifies the scoped virtual result path, preserving hidden physical archive containers and hidden native ancestors. ZIP/TAR member directories without explicit headers inherit hidden status from path components. Archive text may already be bounded-loaded before member filtering; no payload-read/performance claim is made.
