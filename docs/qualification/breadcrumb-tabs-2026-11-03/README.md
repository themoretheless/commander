# Open path-bar folders in tabs — 2026-11-03

Independent Commander extension of cohort #6 [Files folder-tab gestures](https://files.community/docs/features/tabs). Middle-click a path component to create a lazy background tab, or right-click for Open in new tab / Open in background tab. Root, ancestor, current-folder and collapsed components are supported in List, Icons and Columns. Primary ancestor navigation keeps its existing behavior; the current folder now exposes a focusable action button and tab-action hint.

Requests retain native owner and target paths, listing generation and workspace tab revision. The core admits only an absolute lexical component of the captured owner, including the owner itself and filesystem root; siblings, arbitrary children, relative paths, changed views/revisions, pending dialogs and full tab groups refuse. Existing foreground/background tab creation owns lazy loading, source runtime preservation, view settings and capacity policy. There is no preflight listing/stat when capturing a path component.

The old boolean folder-origin flag is now an explicit current-list / Miller / breadcrumb / collapsed-breadcrumb route. Context bindings freeze that route and its revision along with owner, generation and folder. The collapsed-component menu retains its tracked popup while its nested context menu uses separate open/position state; opening the child no longer closes its owner or loses its action. The path chip is a single button owning text and pointer interaction. Header and file-list requests have separate outputs, merged after the pane renders, so the list renderer cannot clear an action emitted by the path bar earlier in the frame.

Four new regressions cover both panes, all views, every path component, foreground/background opening, protected/custom source metadata, lazy tabs, source restoration, invalid/stale/modal/capacity refusal, actual hidden-component middle/context actions, and full-pane header-to-body event delivery for current/root text clicks. Existing frozen-menu tests now include the breadcrumb route and route changes after opening. The formerly failing restoration test now refreshes the restored lazy panel before checking cursor/selection and allows its listing generation to advance; background opening still requires exact generation preservation.
