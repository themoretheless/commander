# Relative-directory exclusion masks — 2026-10-28

Independent follow-up to Double Commander Find Exclude subdirectories ([primary documentation](https://doublecmd.github.io/doc/en/findfiles.html)). Upstream supports folder names and relative/absolute paths. This milestone adds rooted relative path masks to Commander's directory exclusions; absolute path masks remain unsupported. No upstream code copied.

excludedir:vendor/cache now excludes only that root-relative branch and its descendants, preserving other/cache and other/vendor/cache. A mask without / preserves the existing basename-anywhere semantics. Path * and ? never cross a separator; a whole ** component matches zero or more levels. Leading ./ anchors an immediate folder, trailing / is optional, and adjacent ** components collapse without changing matching. Masks retain the existing case policy, Unicode scalar matching, literal punctuation and saved expression/JSON semantics.

Empty/internal dot/parent components, absolute paths, repeated separators and embedded ** within a path component are rejected. Directory masks still classify lexical directories only: matched files and symlinks remain eligible. Native traversal filters directories before descent; indexed search filters actual directory ancestors. ZIP/TAR masks start at the member root, so neither physical archive paths nor synthetic container! components enter the match. Provider prefilters own directory-path evaluation; the shared metadata stage applies only basename leaf masks to avoid inventing a virtual scope.

New tests cover anchored paths, single-component wildcard boundaries, zero/many-level globstar including terminal globstar, adjacent globstars, ./ and trailing slash, Unicode/newline/literal brackets, case, roots/out-of-scope paths, invalid syntax, all-mode expression/JSON round trips, and native/JSON-index/ZIP/TAR matrices. The provider matrix includes root-vs-nested branches, globstar, case, file preservation and synthetic container scope. Earlier basename/directory/symlink/root regressions are retained in the full suite.

compile-rejected.log retains an initial missing Path import. fixture-case.log retains the discovery that cache and CACHE alias on this case-insensitive native volume: the corrected fixture uses distinct cache and CACHE-ONLY names so both native and archive case policy can be tested portably. No product filter was altered to hide this fixture difference.
