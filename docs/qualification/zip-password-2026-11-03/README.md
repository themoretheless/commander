# ZIP/ZIPX password extraction: ZipCrypto and WinZip AES

Source inspiration: cohort #96 [PeaZip encrypted ZIP handling](https://peazip.github.io/encrypt-files.html). Format references: [PKWARE APPNOTE 6.3.10 section 6.1](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) and [WinZip AE-1/AE-2 specification](https://www.winzip.com/en/support/aes-encryption/).

The archive pane provides a masked password field when the ZIP listing has encrypted members. Extract selected/all moves the owned value into the extraction worker and clears the field. An empty password remains a supplied empty value, so valid empty-password archives also extract. Closing/replacing the pane drops its value. The password is runtime-only: no settings/session/preset/history/CSV/metadata serialization is added. egui TextEdit otherwise retains plaintext undo snapshots, so this field clears its undo history each frame. Owned password/derived-key storage, ZipCrypto registers and the custom AES keystream buffer use zeroize; AES and HMAC/SHA-1 primitives enable their zeroization features. This is not a claim that every transient GUI/library/OS/allocator copy is securely erased.

Standard Store/Deflate/BZip2/Deflate64 use zip-rs 9.0.5 password decoding with AES enabled. Bounded LZMA/XZ/Zstandard (93 and legacy 20)/PPMd readers receive an optionally decrypted compressed stream while preserving original metadata. ZipCrypto validates its 12-byte header against CRC or DOS time for descriptor entries. WinZip AES supports 128/192/256-bit keys and AE-1/AE-2, PBKDF2-HMAC-SHA1 with the format's 1000 iterations, little-endian AES-CTR and constant-time verifier/tag comparisons. AE-1 retains ZIP CRC validation; AE-2 uses authentication instead, including compatibility with nonzero ignored CRC fields. Exact decoded size remains required in both versions. PKWARE strong encryption remains explicitly unsupported.

Custom AES composition and end-of-stream authentication follow zip-rs 9.0.5, with its MIT notice preserved. A decoder may reach EOS before consuming all ciphertext. Before returning successful EOF, the adapter drains the remaining ciphertext and checks its HMAC, including bytes already buffered by the decoder. Authentication failure remains a failure on later reads. A cancellation-aware ZIP extraction reader polls the worker flag on each bounded read, including authentication tails. Encrypted directories drain and verify before creation, even with zero decoded bytes. Symlinks retain authentication, bounded target reads and lexical confinement checks. Failed/cancelled regular extraction removes its partial file; existing files remain protected by create_new.

Decoder limits are unchanged after decryption: liblzma has a 64 MiB decoder budget; Zstandard has a 64 MiB back-reference window cap (not total process memory); PPMd has a 64 MiB model-arena cap (additional tables/context/I/O are separate). Password-free archive browsing/metadata remain available; encrypted content search and the separate integrity-check command do not receive a password through this field. Archive encryption/creation and a password manager are separate open features.

## Independent fixtures

Runtime decoding stays in-process Rust. Official 7-Zip 26.05 and OpenSSL are used only to generate/verify qualification fixtures. tool.json checks the already isolated official 7-Zip binary against its prior verified hash; no tooling binary is shipped as an app runtime dependency. Fixture passwords are public test data.

make_empty_password_fixture.py additionally verifies an independently produced empty-password AES/PPMd archive through interactive 7-Zip extraction and the actual Rust worker. make_fixtures.py produces ZipCrypto Store/Deflate/BZip2/Deflate64 archives through 7-Zip. make_custom_fixtures.py independently wraps previously qualified codec packets in deterministic ZipCrypto ZIP records, using Python/zlib key CRC transitions; 7-Zip decrypts and decodes them. make_aes_fixtures.py uses Python hashlib/hmac and OpenSSL AES blocks to wrap those original codec packets in independent AE-1/AE-2 envelopes, plus genuine 7-Zip-produced standard-codec AES archives. extend_standard_aes_fixtures.py adds externally decoded AE-1 metadata/CRC conversions for every standard codec/strength and retains malformed size/tag cases. The matrix includes all three AES strengths, both vendor versions, empty content, descriptor entries, UTF-8 passwords, CRC/size/tag failures, short headers, late authentication, cancellation, policy refusals, directories and Unix symlinks. Their actual fixture hashes and external results are recorded in oracle.json, custom-oracle.json and aes-oracle.json. Genuine 7-Zip archive salts/headers are random, so regeneration changes their hashes.

Oracle boundaries are explicit. 7-Zip 26.05 does not route legacy ZIP method 20; identical encrypted bytes are checked by relabeling only the inner compression method to 93. Its AES/XZ empty-entry route reports data after EOS. It also refuses the deliberate PPMd-after-EOS tail control. For these two envelopes, 7-Zip's AES+Stored route instead verifies the exact compressed plaintext, while the original codec packet comes from its separately qualified fixture. The authenticated PPMd-tail control qualifies the adapter's permissive unread-tail/authentication behavior, not direct 7-Zip ZIP/PPMd-tail interoperability. For directory/symlink envelopes, 7-Zip first verifies their regular-file payload form; only unauthenticated ZIP name/mode metadata is then changed to exercise extraction semantics. No successful external directory-authentication check is inferred from an archiver skipping directory contents.

Initial failures are retained. The first overwrite assertion expected an error rather than skipped_existing; it was corrected. The first XZ policy fixture encoded a valid 48 MiB dictionary and was correctly accepted; it was corrected to 96 MiB and independently rechecked. No policy was relaxed. A final forged-size regression then proved that zip-rs standard AES reading accepted fewer decoded bytes than declared, although 7-Zip rejected the same archives. The shared standard-member adapter now requires exact size at EOF, extending that check to all standard ZIP reads. AE-1 and AE-2, all standard codecs/strengths and negative size/tag extraction are covered after this fix. Compile iterations corrected locked-egui API usage, private zip-rs metadata access, generic extraction metadata helpers and the public scenario catalogue regression.
