# UTF-16 LE/BE search inside binary files — 2026-10-30

Independent Rust adaptation of [Double Commander viewer encoding-aware text search](https://github.com/doublecmd/doublecmd/blob/master/components/viewer/viewercontrol.pas), cohort #3. Public source exposes UTF-16 LE/BE encodings and its text finder decodes characters according to the selected encoding. Inspected through the GitHub connector. No upstream implementation copied; Commander deliberately searches exact encoded bytes in arbitrary binary content rather than decoding the file as a document.

Hex viewer search now offers Hex bytes, UTF-8 text, UTF-16 LE and UTF-16 BE, independent of HEX/Decimal display. Text stays unchanged when switching modes; match state resets. UTF-16 encodes Rust Unicode scalars into code units with explicit endian order, including surrogate pairs for supplementary characters. No implicit BOM, normalization, case folding or whitespace trimming. An explicit U+FEFF in the query is encoded literally. Empty input and more than 256 encoded bytes are rejected. Encoding checks the limit incrementally and does not allocate a large intermediate string.

Both new choices use the existing bounded streaming KMP reader, progress/cancellation, file-stamp validation and forward/backward overlap semantics. Byte offsets need not be aligned: this is useful for embedded strings, including code units split over page/read boundaries. Invalid surrounding encoded data has no effect. This does not claim document decoding or full upstream encoding parity.

Two regressions cover hard-coded little/big endian vectors with Cyrillic, a surrogate pair and NUL, explicit BOM, empty/encoded-size limits and canonical distinctions. Actual worker searches in both modes verify odd offsets 4095/65535, split code units across 4096/65536 boundaries, forward/forward/backward matches and unchanged contents. Native HexSearch retains hex and UTF-8 interactions, then selects LE and BE while preserving the query. Each mode finds two odd-offset matches and returns backward to the first; final readiness requires BE, phase 54 and match at 110001.
