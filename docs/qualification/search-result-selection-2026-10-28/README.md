# Group selection in Find results — 2026-10-28

Independent adaptation of Double Commander's [multi-selection in search results](https://doublecmd.github.io/doc/en/findfiles.html), with macOS Cmd toggling and Commander's existing Find actions. No upstream code copied.

Rows now have selection checkboxes. Cmd-click toggles a row; Shift-click adds the visible interval from the last individual selection anchor in the current time/display order. Without a visible anchor it toggles the target and establishes an anchor. Ordinary clicks retain reveal behavior and unmodified double-click retains opening. Selected rows are highlighted independently of the keyboard cursor. Copy selected copies selected visible paths through the established clipboard formatter and port; Copy paths continues to copy every visible result. Clear selection resets both selected locations and anchor. No pane selection or filesystem mutation occurs.

Selection is keyed by SearchLocation, so hard-link aliases and distinct archive member indexes do not collapse. Incoming results and sorting retain selected locations. Hidden rows are deselected, a hidden anchor is discarded, and restoring hidden rows does not restore their selection. Successful new search and invalid-root reset paths clear selection. Copy selected retains virtual archive paths and displayed order, with the same control escaping, error feedback and streaming limits as Copy paths.

The focused regression covers additive ranges excluding hidden rows, sorting/incoming batches, time grouping, shared native identities, separate duplicate archive-member indexes, hide/restore, toggling, stale targets and clear. Existing path-copy regressions remain active. Native SearchResults QA retains previous hiding/restoration/background-tab/keyboard/copy-all checks, then selects notes.md with a checkbox, Shift-clicks Design and copies selected paths. Readiness requires two selected locations, the exact expected payload, query focus and unchanged Find/tab invariants. Exactly two recording clipboard writes are allowed (all visible, then selected); real system clipboard remains untouched and every other effect counter must be zero.
