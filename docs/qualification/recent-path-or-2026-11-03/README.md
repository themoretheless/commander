# OR alternatives in recent-folder path terms — 2026-11-03

Independent adaptation of cohort #75 [fzf's standalone-bar OR grouping](https://github.com/junegunn/fzf#search-syntax). Cmd+P's Ordered path terms mode accepts work src$ | tests$: work is required, followed by either src or tests in the final folder. A bar combines adjacent atoms; separate groups remain AND conditions, so work | other src$ means (work OR other) then src. This is an adaptation to Commander's existing ordered exact-path matching, not full fzf syntax/fuzzy parity.

Alternatives can contain anchored terms, inverse terms, Unicode or escaped whitespace. An inverse alternative tests the complete path without consuming a position. The last positive term of the successful branch still must occur in the final folder; anchors and trailing-separator normalization retain their previous semantics. A standalone literal pipe can be escaped as \|; embedded a|b stays literal. Leading, trailing and consecutive OR operators refuse with an inline error and no candidates. Initial ! retains Omnibar shell routing, so inverse recent-folder queries follow a positive term.

The shared caps remain 32 atom conditions and 1024 raw UTF-8 bytes. Matching keeps two bounded reverse frontiers (no positive consumed / positive consumed), retaining the largest eligible prefix for each state. It does not expand combinations in production. Scope, frecency/chronological ordering, history identity and usage statistics stay unchanged; matching performs no filesystem probes.

One Rust regression covers precedence/order, mixed inverse alternatives, anchors, literal pipes, Unicode, spaces, malformed operators and caps. Another compares alternative frontiers with exhaustive branch expansion over multiple path families and verifies both ranking modes and unchanged usage. Existing path-term regressions remain included. The extended native recent-folder scenario types eight new queries, including malformed syntax and recovery; the verifier expands branches independently and matches forward with Python regex predicates. It checks prior exclusions/anchors/escaped spaces, exact visible paths, history/stats, untouched source bytes, no navigation and zero native effects.
