# Copy listing as JSON

Independent adaptation of [Dust's machine-readable JSON export](https://github.com/bootandy/dust/blob/master/README.md), cohort #82, over Commander's retained file pane. No upstream code copied; this is Commander's own versioned schema.

**Copy listing as JSON** in the palette exports current display order. With no local selection it uses visible rows; with a local selection it uses only visible selected rows, matching the existing listing formats. The report records listing/visible/selected/exported counts and hidden selected rows, current folder, text query, quick-filter facets and view/sort configuration. Hidden selections are counted, not silently exported. No recursive scan or Info-time metadata read is performed.

Rows retain lossless absolute paths, original names, lexical kind when captured, regular-file logical bytes, allocated bytes, displayed size and the listed UTC mtime with subsecond precision. Directory/symlink file-size and allocation facts are null; displayed sizes and listed mtime may reflect the existing target-following presentation of a link. Allocated bytes are a filesystem observation, not exclusive/reclaimable ownership. Paths with non-UTF-8 bytes, NUL or parent traversal fail instead of becoming lossy text. JSON strings preserve controls and formula-like names without spreadsheet escaping. Unsigned byte counts retain their complete integer representation; consumers need integer-aware parsers for values above 2^53.

Reports require a complete retained listing and are limited to **1 MiB** by a streaming writer. Invalid/oversized reports stage no CopyText request, preserving the clipboard. A selection whose visible intersection is empty leaves the command unavailable. This is a read-only snapshot report, not a fresh filesystem verification, recursive inventory or replayable transfer plan.

## Validation

- Four new regressions cover projection/selection/hidden counts, directory and link facts, snapshot export after source deletion, exact u64 values, nanosecond UTC, control/formula-like names, malformed/lossy paths, bound enforcement and actual workspace command success/failure without partial clipboard requests.
- This host rejects creation of invalid UTF-8 filenames; lossy-path refusal is tested with synthetic paths in retained objects rather than silently skipping coverage.
- Full suite **3116 passed / 3 ignored**; all six required commands in `checks.json` exit zero. Full tests retain external checksum-oracle coverage with restored official RHash 1.4.6 and registry b3sum 1.8.7. Versions/hashes/paths are in `validators.json`; these tools live under ignored `target/qualification-tools`, not `/tmp`.
- Native `listing_json` invokes actual Sort by allocated size and Copy listing as JSON palette actions. Two exact recording clipboard writes capture the complete 9-row view and a 2-row visible selection while one selected row remains hidden. Selection/filter setup is QA fixture state; export dispatch is the real UI command.
- Existing native `allocated_sort` checks all four metric/direction transitions on the same executable. Both **14/14**; the new scene has exactly two recording clipboard effects, the regression scene zero, all other native-port effects zero.
- `verify.py` validates final executable hashes, commands, manifests, both payloads, scope/counts, order, nullable link/folder facts, exact paths and allocation/size separation. Captures are durable under `native-captures/`; `prepare_capture.py` prepares the owned wrapper for launch through CUA.

The initial native export produced the expected JSON but failed the layout/capture gate: filtered selected content expanded the left pane into its neighbor. That failed run remains under native-captures and its launch record under before-layout-fix. A fixed listing viewport now prevents intrinsic content width from propagating to the resizable pane owner while retaining its user-selected width and clipping. Two additional UI regressions cover filtered/selected rendering and oversized child content at three pane widths. The final native captures, not the initial payloads alone, must satisfy all geometry checks.
