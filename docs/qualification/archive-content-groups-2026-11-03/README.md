# ZIP content SHA-256 groups

Independent extension of cohort #96 [PeaZip checksum grouping](https://peazip.github.io/duplicates-hash-checksum.html), using Commander's existing verified ZIP decoder. The reference distinguishes stored archive checksums and strong-hash comparisons; this implementation actually decodes ZIP members before comparing SHA-256 and size. It is not a copied upstream archive scanner and does not claim a new byte-to-byte comparison. No dependency was added.

Find matching contents runs in the existing background archive-check worker, consumes/clears the ephemeral password and reads every entry without extraction. Only safe regular files become hash candidates; directories, symlinks, other record kinds and unsafe paths are still checked but not grouped. Members enter groups only after complete size/CRC/AES verification. A later failure, cancellation, source-stamp mismatch or budget refusal returns an error without partial groups. SHA-256 plus actual checked size defines a group; equal CRC/size alone is insufficient. Limits remain 128 MiB decoded and 100000 members, with an additional 8 MiB charged identity-metadata budget. Raw reads remain cancellation-aware, including AES authentication tails. Ordinary integrity checking keeps its existing mode and report behavior.

Content grouping always validates strict ZIP headers and enables the pane's strict control. This is necessary because the locked zip-rs reader coalesces duplicate central-directory names. Rather than silently skipping records, ambiguous/duplicate names and inconsistent headers refuse the content scan. Support for comparing every record of duplicate-name ZIP containers remains open. Ordinary permissive Test archive remains separately selectable.

Successful results show group/member counts and a bounded expandable list of SHA-256 values and paths (first 100 groups, first ten paths each, with explicit remaining counts). Select scanned content matches adds all reported members, including hidden ones, after an atomic original-index/path/size/type match against the current listing. A stale or ambiguous listing refuses the whole selection. Existing selections are retained. Results are observations from the last completed scan, not a fresh filesystem verification at selection time. The existing text/JSON check report export retains its check-summary schema and does not yet export the group payload; member-list export can copy a selected set.

Five Rust regressions cover a real CRC-32 collision with different SHA-256 values, repeated/empty contents, unsafe/symlink/directory exclusion, duplicate-name refusal, Unicode-password encrypted/plaintext grouping, missing/wrong passwords, authentication error, decoded filename metadata/member/decoded budgets, cancellation, source mutation, worker delivery and atomic selection identity mapping. The first duplicate-name fixture attempt and the later coalescing discovery are retained in focused diagnostic logs. Final tests use distinct ZIP writer names and deliberate header mutation for the duplicate-name refusal.

Native ArchiveContentGroups uses 24 raw pointer/text phases: wrong password, correct Unicode password, then selection of the exact three matching entries and expansion of the group details. The digest and all three displayed paths must be visible. Observations require an empty password field, unchanged archive bytes and no extracted members. The captured ZIP fixture is preserved; Python independently checks its names/plain content, exact SHA-256 against the prior fixture payload and group identities. ArchivePassword is recaptured as a regression for ordinary extraction, integrity checking and four report clipboard writes. Final common gate/capture results follow below. Raw logs are preserved verbatim via local .gitattributes.

The initial native run reached correct groups and three selected entries, but its final readiness predicate incorrectly treated ZIP indices as sorted-list positions. The final driver records both identities and expects positions 1,2,3 for ZIP indices 0,1,2; the failed capture is retained. The metadata budget was also tightened to charge decoded filename bytes, with a CP437 expansion boundary regression; all final gates are rerun after these changes.

All seven final gates passed: 3454 tests passed, 0 failed, 3 ignored; strict visual-QA Clippy, dependency audit, build, ordinary check, formatting and diff checks passed. Ordinary check retains the existing unused_response warning in diff_find.rs. Final captures 1793677784288535000/archive_content_groups and 1793677810189422000/archive_password each passed 14/14 against the final binary. Content grouping recorded zero native effects; the ordinary password scenario recorded exactly four clipboard writes and no other effects. Python independently verified group SHA-256/size/member identities, the mapping to sorted-list selections, visible expanded digest/paths, unchanged archive/no extraction and all ordinary password/check/report cases. Both final framebuffers were visually inspected. Earlier captures/gates remain historical diagnostics, not final binary qualification.
