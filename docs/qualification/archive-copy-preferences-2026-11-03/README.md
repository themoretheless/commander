# Remember archive copy rules across archives and sessions — 2026-11-03

Commander extension inspired by cohort #1 [Kiorg app state persistence](https://github.com/houqp/kiorg#key-features). Valid archive copy rules are reused when opening/reopening another archive and survive session save/restore. The remembered policy includes replica count, ordering, protection/candidate glob lists, filename-only mode, case mode and modified-before cutoff. It never includes an archive path, password, scan result, selected member IDs or selection undo/redo history.

The versioned policy block is isolated as a JSON value so missing, malformed or future preference data cannot prevent the rest of the session from loading. All required policy fields and the exact schema version must be present; unknown keys/enum values, counts outside 1..=100000 and invalid/oversized glob/date values fall back to defaults. Runtime edits only replace the remembered policy when valid; an invalid pending field preserves the last valid choice. Newly opened archives keep an empty selection and empty selection history; rules never auto-select copies. The UI describes valid-rule remembering explicitly.

Two regressions cover all six orderings, flags and all remembered fields, policy-only serialization, malformed/unknown versions, validation failures, old sessions and real atomic session save/load. Native QA retains the full policy/history sequence, saves through the injected ephemeral session store, checks last-valid fallback for an invalid pending candidate, clears/restores cached preferences through the startup loader and reopens the archive. A fresh real Find matching contents click confirms the policy survived while selection/history stayed empty. The ordinary TAR/ZIP integration/export scenes remain separate. verify.py checks all prior receipts and exact saved/restored/reopened preference values and fixture content groups.

Reproduce with run_checks.py, then prepare_capture.py and CUA launch separately for archive_protection_modes, archive_tar_content_groups and archive_content_groups, then verify.py. Native reopen runs within the same process using the actual session store/load path; a full desktop process-relaunch and additional platform qualification remain open.
