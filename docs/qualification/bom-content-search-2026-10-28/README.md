# BOM-aware Unicode content search — 2026-10-28

Independent adaptation of ripgrep BOM sniffing / automatic UTF-16 transcoding ([primary guide](https://github.com/BurntSushi/ripgrep/blob/master/GUIDE.md#file-encoding)), cohort #76. Commander also supports BOM-marked UTF-32 input using the same owned decoder. No upstream code copied, new dependency installed or external search program invoked.

A shared search_text module classifies the encoded 8-KiB head and decodes supplied byte prefixes. UTF-8 BOM, UTF-16LE/BE and UTF-32LE/BE signatures are recognized in longest-signature order. Only the initial signature is removed; an embedded/payload U+FEFF is preserved. UTF-16 uses a unit iterator with no intermediate unit vector; UTF-32 validates scalar values. Malformed units and incomplete tails become U+FFFD, consistent with existing lossy UTF-8 search. Unmarked UTF-16 is not guessed and remains subject to raw-NUL detection. Marked text is checked for zero code units, avoiding false binary classification from structural zero bytes.

Native reads, new index snapshots and owned ZIP/TAR member text use the same decoder. File sizes, raw read/member/stream/bomb limits, regular-file guards and cancellation owners stay in place. Decoded character ranges and word/line semantics operate after BOM removal. Existing EOF/completeness gates and conservative trailing-replacement handling prevent a cut surrogate pair from inventing a whole-word boundary; safe earlier prefix hits remain eligible. No general encoding picker, legacy code-page conversion or arbitrary binary-search mode is added.

Index quota preflight formerly compared encoded file size against remaining decoded-text capacity. quota-reproduced.log first fails on UTF-8 BOM overhead; the final fixture covers UTF-16/32 contraction too. Preflight now uses a proven lower bound (at most four signature bytes and up to four encoded bytes per scalar), then enforces the actual decoded length. A CJK expansion fixture confirms the hard decoded quota still rejects excess text, and full JSON budget regressions remain required. Existing cached strings are not migrated and old missing Unicode content requires rebuild; schema unchanged.

Six focused regressions cover literal endian goldens and UTF-32/16 signature precedence, supplementary/Cyrillic/accented text, payload BOM retention, malformed/truncated units at every prefix length, NUL/unmarked input, decoded quota contraction/expansion, all text modes across native/JSON-index/ZIP/TAR (ordinary/whole-word/whole-line/negative conditions), BOM-only empty text and binary skipped accounting. A real 16-MiB UTF-16 fixture cuts a surrogate pair and proves both tail rejection and safe earlier matches. The final full suite includes the final contains-based binary-head implementation.
