# RTF text preview — 2026-10-30

Independent Rust adaptation of [ranger's RTF text preview](https://github.com/ranger/ranger/blob/master/ranger/data/scope.sh), cohort #30. Ranger uses catdoc; Commander parses bounded bytes directly and uses the existing text worker/cache/find/copy path. No upstream implementation copied, converter installed or external program invoked. [Microsoft RTF syntax](https://learn.microsoft.com/en-us/previous-versions/office/developer/office2000/aa140284(v=office.10)) is the primary grammar reference. This is an independently tested text extractor, not a complete RTF reader qualification.

The parser retains visible body text, paragraphs/line/page/section breaks, tabs and table cell/row delimiters, common punctuation control words and escaped braces/backslashes. It decodes signed UTF-16 `u` units, surrogate pairs, scoped `uc` fallback counts (including hex/control/binary fallback tokens) and the Unicode branch of `upr`/`ud`. Source CR/LF is ignored; escaped line breaks produce newlines. Font/document codepages decode strictly, without replacement: Windows-874/1250–1258, Shift-JIS, GBK, EUC-KR, Big5, Mac Roman and UTF-8. Font `cpg` takes priority over `fcharset`; font groups and default-font restoration retain their scope. ANSI without a codepage uses Windows-1252; OEM/Symbol or unknown active byte encodings report an error.

Font/style/color tables, metadata, headers/footers, notes/comments, pictures/shapes/objects, hidden/deleted text and unknown starred destinations are omitted. Fields retain only their visible result, never instructions or executable/URL behavior. Binary spans are length-checked and skipped before interpreting braces. No filesystem extraction or resource resolution occurs. Find/selection/copy operate on extracted text; native UI labels RTF as text only. Tables remain text with tabs, including terminal cells.

Admission: 4 MiB raw input, 256 KiB UTF-8 text, 128 nested groups and 200,000 parser tokens. Existing regular-file/fingerprint/handle/path checks and cancellation surround extraction; the parser also checks cancellation during scanning. Truncation, malformed syntax, numeric/Unicode errors and exceeded bounds return an error rather than partial text. HTML-encapsulated RTF is explicitly unsupported. There is no claim of Office layout, styles, automatic numbering, field recalculation, embedded media, footnotes, RTFD, compressed RTF, OEM/Symbol conversion or complete compatibility with third-party documents.

Eight new tests cover the native fixture, group/fallback/Unicode alternatives, symbols, inert destinations/binary data, independent hidden/deleted state, multibyte fonts and encoding priority, invalid/truncated prefixes, bounds/cancellation, plus actual filesystem-provider identity and input-budget behavior. The native RtfPreview scenario uses Windows-1252 accents, a Cyrillic font and a surrogate-pair emoji; it searches `message` and verifies exactly copied text, excluding author/unknown/picture payloads.

Final verification: full locked visual-qa suite **2716 passed, 0 failed, 3 ignored**; all-target visual-qa Clippy with warnings denied, default-feature locked check, locked visual-qa build, fmt and diff checks passed. Fresh CUA-launched RtfPreview passed **14/14**, with exactly one recording clipboard write and all other native effects zero. Its manifest postdates the launch record and matches the final binary SHA-256. Frame inspected: RTF label, accented/Cyrillic/emoji text, table text, one highlighted `message` and copied-text notification are visible; no author/picture/unknown payload. Fixture clipboard bytes and displayed content are asserted by the scenario before capture. Artifacts live in `rtf_preview`; source hashes accompany this report.
