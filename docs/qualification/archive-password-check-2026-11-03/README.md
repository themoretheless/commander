# Password-fed ZIP integrity checking

Adaptation of cohort #96 [PeaZip's use of archive tests with supplied passwords](https://peazip.github.io/extract-encrypted-files). The archive pane's masked ZIP password now applies to both extraction and Test archive. Starting either operation moves the owned value into its worker and clears the field; the field is disabled while either worker runs. Empty and UTF-8 password values are preserved. Passwords remain runtime-only zeroizing state, with the existing per-frame undo-history cleanup and no added persistence or diagnostic interpolation.

The checker passes borrowed password bytes to the already qualified shared ZIP reader. Standard and bounded codecs retain ZipCrypto/AES decoding, AE-1 CRC and AE-2 authentication behavior, exact-size checking and whole-envelope authentication after codec EOS. Existing 128 MiB aggregate decoded-byte and 100000-member limits, cancellation-aware compressed reads, regular-file/no-symlink input checks, overlap rejection and before/after source identity/change stamps remain in place. A complete report requires every member and all source checks to succeed. A single password is used per run; per-member password maps and partial diagnostic reports are separate open features.

The report summary now describes CRC/size checks and AES authentication when present. TAR reports/stream checks are unchanged. This feature reads the archive without extracting members; password-fed content search, archive encryption/creation and a password manager remain separate work.

Five new Rust regressions qualify the change. The matrix reuses the independent fixtures delivered in ../zip-password-2026-11-03, covering all standard codecs and AES strengths/versions, bounded codecs including legacy method 20, ZipCrypto descriptors, empty encrypted streams/directories and actual empty/UTF-8-password workers. Negative cases cover missing/wrong passwords, CRC/size/tag failures, directory tags and an unread ciphertext tail. Tests assert exact report counts/progress, unchanged source bytes and no extracted entries. Budget, cancellation and source-replacement refusals remain fail-closed. The first source-replacement test reused progress from a prior cancelled operation, causing its callback to run before the new check captured its stamp; resetting the test's counter models the fresh per-worker counter correctly. No source-stamp guard was relaxed. An existing summary-prefix assertion also caught a wording change; the summary retains its ZIP CRC prefix while clarifying size and AES coverage.

make_mixed_fixtures.py combines immutable, already qualified encrypted member packets under distinct names. An independent official 7-Zip test accepts the mixed ZipCrypto+AES archive and rejects its late-HMAC-failure counterpart; decoded good-member bytes also match independent expectations. No decryption tool is shipped or called at runtime. The inherited fixture oracle limitations (method-20 relabeling and decomposed empty-XZ/PPMd-tail checks) remain documented in the original qualification; they are not broadened here.

Native ArchivePassword extends from 24 to 40 raw-input phases. It retains wrong/correct/repeated extraction, then types a wrong password, clicks the actual Test archive button, observes failure with an empty field, types the correct Unicode password and observes a complete byte-counted report. It scrolls real controls into view and requires the final empty password field and check result visible together. Read-only observations confirm the existing extracted file remains unchanged. There is no direct state seeding after fixture setup. ArchiveMetadata's ten states are also recaptured against the final build. verify.py checks all observations, 14 common gates per scene, zero recording native effects and exact final-binary hash equality.

Raw command logs are preserved byte-for-byte as binary Git evidence with qualification-local .gitattributes. Final gate and native receipt results are recorded below.
