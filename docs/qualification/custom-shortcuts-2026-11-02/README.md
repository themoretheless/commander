# Custom workspace shortcuts

Independent adaptation of [Kiorg's configurable shortcut sequences](https://github.com/houqp/kiorg/blob/50aea44c9b4308b98f757574c527b7e0d3a344fe/crates/kiorg/src/config/shortcuts.rs), cohort #1. Commander already has recent-folder frecency navigation; this transfer adds user-defined key sequences for commands in Commander's command catalog.

Open **Keyboard shortcuts (F1)**, use **Add shortcut**, enter one to four space-separated strokes (for example `Alt+G H`), choose a command and press **Apply shortcuts**. Up to 64 bindings are supported. Remove/Clear draft edit the draft; Apply is the only live replacement. Duplicate sequences and prefix conflicts are refused. Failed Apply retains the previous active/saved bindings. Keys override the normal workspace mapping; Escape is reserved to cancel an unfinished sequence. Prefixes expire after one second. A transient prefix capsule reflects current pending state and disappears on completion/cancellation/expiry, rather than leaving a stale notification.

The existing key-command executor retains command availability and operation guards. Fields, modals, pane tools, active previews, hex viewer and context menus retain input ownership. A pending sequence is cancelled when pane/tab/path ownership changes or another surface takes input. Exact modifiers are compared; Ctrl maps to the primary-command modifier on non-macOS hosts. Auto-repeat events do not repeatedly execute configured actions. Claimed input frames suppress their key/text fall-through into built-in bindings or filename type-ahead. Built-in behavior is unchanged with no applied bindings.

Settings travel in the existing atomic session store. Legacy sessions default to no custom shortcuts. Invalid/future shortcut preferences are disabled with a visible error and retained unchanged in the saved session until the user explicitly applies a replacement; other session settings still load. Editor drafts are bounded. The UI shows that changes save with the session; Apply is not a separate disk-write claim.

Six new regressions cover parsing/catalog validation, row/stroke/prefix/modifier bounds, timeout/mismatch/Escape, same-frame key/text consumption, owner cancellation, actual egui Apply clicks (including invalid-draft preservation), saved preference preservation, and a real atomic session save/reopen plus legacy field absence. The native scenario seeds two editable draft rows, opens Keyboard shortcuts through the workspace command and clicks the real Apply button. It then sends the configured sequence while that modal is open (no workspace effect), closes the dialog and sends `Alt+G H` / `Alt+G S` through the normal key handler. The hidden fixture appears and the active pane's natural-name order reverses; the other pane retains its visibility setting and both roots stay unchanged. Draft Add/command-dropdown/text-entry and physical OS keyboard input are not separately qualified by that native scenario.
