# Sync plan clipboard reports — 2026-10-31

Independently adapts the [Double Commander synchronization tool's column-copy workflow](https://doublecmd.github.io/doc/en/syncdirs.html) (cohort #3). CSV and `commander.sync-plan-report` v1 JSON are Commander-specific report formats; no upstream implementation or replay compatibility is claimed.

**Copy scope** selects **Full plan** (default) or **Shown rows**, then **Copy plan CSV / JSON** copies the retained plan after its async scan has finished. Scan/error/missing-stamp states disable copying; the export owner also rejects them and roots inconsistent with the captured stamp. A same-frame policy/refresh request refuses export rather than mislabelling old rows. Copy returns through the existing clipboard owner before any Apply processing and never starts synchronization.

Both formats retain original 1-based row numbers/order, names, stable status/direction keys, known original left/right paths, selected source and target folder, plus paired-file comparison display text when available. Skipped rows have no selected source/target; unavailable sides remain null/empty. The target is a folder, not an invented final destination filename. Display comparison strings are not machine-readable raw byte/timestamp facts. Metadata matches and uncompared folder pairs are explicitly distinguished from byte equality.

JSON includes captured roots, copy-only policy, shallow name/size/mtime comparison method, export scope, query/category and full/exported row/action counts. CSV repeats that context per row in its header-defined columns. Empty CSV scopes contain only the header; empty JSON still retains its context. Full plan includes hidden rows even while a query is active. Shown rows uses original plan indices from the refreshed review projection; invalid/duplicate/out-of-range projections are refused. No rows are modified during formatting, and no report is imported/executed.

Serialization is limited to 1 MiB using a bounded writer. CSV quoting preserves Unicode, commas, quotes, newlines, whitespace and formula-looking names literally; JSON escaping is included in the size limit. Oversize/errors return no partial text for clipboard writing. Exported native paths must be lossless UTF-8; unsupported paths are refused instead of silently changing identity. Reports describe the retained snapshot and current directions, not a new filesystem scan, guard approval, dry-run execution record or a guarantee the plan is still applicable. Existing Apply revalidation remains authoritative.

Initial native success and the host-APFS-incompatible test fixture are retained under `before-test-fixture-fix/`. The non-UTF-8 test now supplies a retained provider PathBuf, rather than asking APFS to create an unsupported name. Full sync/runtime/content/recursive/delete parity remains open.
