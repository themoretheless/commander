# Clipboard archive-check reports

Adaptation of cohort #96 [PeaZip's archive test/list task-log export](https://peazip.github.io/how-to-open-rar-tar-zip-files.html). Commander adds Copy check report and Copy check report JSON to the last completed check attempt. This milestone provides clipboard export through the existing clipboard port; direct file-save dialogs and per-member task logs remain separate features.

The report contains a versioned schema, archive path/format, UTC result-recording time, complete/incomplete status, strict-header mode, successful member/decoded-byte counts and an error when present. An unsuccessful check has unavailable/null counts rather than invented zeros. Its strict mode is captured when the operation starts, independent of a later checkbox change. A success uses its actual Report mode. Stop/disconnection results remain incomplete. The recording timestamp describes when the UI recorded that result, not a new filesystem verification or a cryptographic binding to the current file contents. Format on a failure is inferred from the requested archive extension. Copying a report never reopens or rereads the archive.

The formatter accepts no password argument and serializes only explicit report metadata. Password handling and per-frame undo cleanup are unchanged. Text paths/errors are JSON-quoted so embedded LF/CR cannot create fake line-oriented status fields; JSON uses serde escaping. UTF-8 paths are required, matching existing archive-list clipboard policy; non-UTF-8 paths fail explicitly rather than replacing bytes. A bounded writer caps either output at 4 MiB without truncation or partial clipboard updates. No dependencies are added.

Four new Rust regressions cover actual success metadata versus an inconsistent requested mode, UTC timestamp serialization, incomplete/unknown counts and modes, newline injection, oversized escaped output and Unix non-UTF-8 refusal. The native clipboard-count regression was updated to require the scenario's four new recording writes; its initial failure is retained rather than relaxing effect isolation.

Native ArchivePassword extends from 43 to 55 raw-input phases. After a wrong-password check it toggles strict mode on, then clicks the real text/JSON export buttons; the copied failure reports must still say strict=false. It next checks with the correct Unicode password in strict mode and clicks both buttons again; those reports must be complete, strict=true and have exact counts. Four clipboard payloads are saved from the recording service, parsed/checked independently and required not to contain either supplied password. Source/extracted-byte assertions, field clearing and the existing extraction/repeat cases remain. The OS clipboard is not modified by native qualification: the application uses its recording clipboard port. ArchiveMetadata is also recaptured with no clipboard writes. Final common gates, source hashes and exact built-binary hash checks identify the qualified code.

Raw diagnostic logs are preserved verbatim through qualification-local .gitattributes. Final gate and receipt results follow below.
