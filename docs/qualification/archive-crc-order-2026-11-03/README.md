# Archive CRC-32 ordering

Independent adaptation of cohort #96 [PeaZip archive CRC-column sorting](https://peazip.github.io/duplicates-hash-checksum.html). ZIP/ZIPX archives gain CRC-32 in Sort and, at pane widths of at least 500 points, a clickable CRC-32 column showing declared hexadecimal values. Narrow panes retain the menu sort. TAR does not offer this unavailable sort field.

Sort compares numeric CRCs ascending by default; header clicks reverse it. Missing CRCs, including AE-2 and synthetic navigation folders, remain unavailable rather than zero. Within real member ordering, unknown values stay last in both directions; the explicit Folders first preference retains precedence. Equal CRCs retain ascending natural/lexical name ties and exact entry/index identity, including duplicate paths. Sorting never reads payloads or changes selections. CRC coincidence is a comparison aid and does not prove byte identity. Automatic archive deduplication remains separate.

A new Rust regression covers zero/max/unknown checksums, repeated CRCs and names, natural/lexical ties, reverse direction, folders-first precedence, toggle defaults and ZIP/TAR availability. Native ArchiveMetadata retains all eleven metadata observations, then clicks the actual CRC header in both directions. Snapshots record applied row positions, original listing IDs, CRC declarations and unchanged selections. Independent Python verification checks CRC values against separately verified metadata and exact numeric order, including the unknown tail. ArchiveExport rechecks its five exact recording clipboard copies. Existing CSV schema is unchanged in this milestone.
