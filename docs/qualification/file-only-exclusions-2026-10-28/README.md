# File-only search exclusions — 2026-10-28

Independent adaptation of Double Commander Find files “Exclude files” ([primary documentation](https://doublecmd.github.io/doc/en/findfiles.html)), a member of the 99-repository cohort. No upstream implementation copied.

Commander previously offered exclude: masks that remove every matching entry and prune matching directories and archive containers. New excludefile: whole-name masks only filter non-directory results. A cache.tmp directory and its children remain searchable while matching temporary files are removed. Multiple masks combine through AND, meaning any matching mask excludes the file. The existing * and ? compiler provides Unicode character matching and literal punctuation, with case-insensitive defaults and case:sensitive support independent of text match mode. Spaces can be quoted; empty/path/oversized masks are rejected. Chips, explanations, canonical expressions and JSON saved queries retain the new predicate.

The compiled filter is shared by native, indexed, ZIP and TAR results. It does not prune directories or suppress archive member inspection when only the container result is excluded. Existing exclude: and archives:off behavior remains available. Non-directory here uses the existing entry model (including symbolic links); it is not the lexical type:regular predicate.

Regression tests cover all text modes, case policy, AND composition, literal brackets, Unicode and newline-containing names, directories, invalid masks, expression/JSON round trips, a JSON-roundtripped real index and native/ZIP/TAR search. The provider matrix proves that matching directory ancestors and filtered archive containers retain their children, while exclude: still prunes them. Binary excluded files do not count as skipped content; unfiltered binary ZIP/TAR container results still contribute two skips, separately from their searchable members. Initial fixture expectations omitted those normal container skips; fixture-adjustment.log retains that failure and the final fixture asserts them explicitly. No performance claim: archive providers may preload bounded text before metadata filtering.
