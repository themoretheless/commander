# Bzip2, XZ and Zstandard TAR — 2026-10-30

Independent Rust integration of formats supported by [ouch](https://github.com/ouch-org/ouch/blob/main/README.md), cohort #97. Commander previously admitted ZIP, TAR and gzip TAR. It now admits tar.bz2 (`tbz`, `tbz2`), tar.xz (`txz`) and tar.zst (`tzst`, `tar.zstd`), case-insensitively. Standalone compressed streams are not interpreted as TAR merely from `.xz`/`.bz2`/`.zst`. No ouch implementation copied or external converter installed.

The common TAR listing/content visitor receives streaming bzip2, XZ or Zstandard readers. Member identity/order, raw names, metadata, unsafe-path/link handling, tree navigation, search queries and budgets keep their existing owners. Both live and indexed search use the same visitor. Coarse Archives classification also recognizes the short aliases. New decoder dependencies are bzip2 0.6.1, xz2 0.1.7 and zstd 0.13.3, with seven packages added to the lockfile from the local registry cache. XZ explicitly enables static linking rather than a host Homebrew liblzma dependency.

The decoded TAR inspection budget remains 128 MiB, including skipped payloads; exhausted inspection reports truncation/partial results. Existing member/text/archive budgets apply. XZ configures a 64 MiB decoder-memory limit; Zstandard configures maximum back-reference distance 2^26 (not a claim of total decoder memory). Bzip2 uses its bounded block decoder. Reads below the decompressor check cancellation as well as decoded TAR reads above it. Concatenated compression frames can span a TAR header. Listing stops at TAR's logical end and is not a complete trailing-frame/checksum validator.

The existing selected-member system-tar extraction path remains responsible for names and metadata. This host's bsdtar lacks Zstandard support, so all three new formats first decode into an exclusively created temporary raw TAR (Unix mode 0600, random name), capped at 128 MiB and cancellation-checked. It is owned by RAII and removed on return, including errors/cancellation; system tar only sees raw TAR. Staging drains the decoder to EOF before starting member extraction and does not write extracted member paths. Plain/gzip TAR extraction behavior remains unchanged. Distribution on other platforms and other system-tar versions remains unqualified.

Five new regressions cover bounded/cancelled scans, concatenated frames and broken/truncated inputs, private staging permissions/cleanup/size/cancellation/source preservation, actual selected extraction of Unicode/glob/option-like names with existing-file preservation and mtime, and indexed content search. Existing raw/gzip content/search regressions now include all five TAR kinds; live provider results cover all five containers. Native browser scenarios for each new codec reuse the seven-member natural-sort/folder-navigation/selection contract.
