# Preferred archive keepers — 2026-11-03

Independent Commander extension inspired by cohort #85 [fclones path-aware keeper/candidate controls](https://raw.githubusercontent.com/pkolaczk/fclones/main/fclones/src/config.rs). Prefer keepers (globs) ranks eligible matching members ahead of nonmatches when filling remaining keeper slots. The existing main priority, ordered tie breakers and original entry number resolve equal-preference matches. Patterns are OR alternatives; line order is not a priority chain. No matches fall back to existing ranking.

This is a soft preference, distinct from fclones/Commander hard keep-path protection. More preferred matches than keeper slots may still be selected as extra copies. Protected members and noncandidate members remain kept and consume slots first; preferences neither increase the minimum count nor override protection, candidate restrictions or the all-members date cutoff. Both per-group and global actions share the same atomic identity/overlap validation. Pending edits do not change selection; invalid patterns disable both actions and preserve the last valid saved rules.

Preferred patterns share Filename only / Match case modes and existing bounds: at most 16 nonempty globs, 256 characters each, 8192 total characters. Blank lines are ignored, spaces remain literal, CRLF is accepted; full-path * does not cross folders, ** does. Active matching requires strict UTF-8 paths. Valid preferences are saved with the existing versioned policy/session path; older policies lacking preferred_globs get an empty preference without losing other fields. Invalid/future saved blocks retain existing default fallback behavior. Archive open/reopen does not auto-select members.

Three new Rust regressions cover all six primary priorities, counts, hard protection/noncandidates, skipped unknown dates, filename/case/path modes, OR patterns, invalid/oversized lists, stale/non-UTF-8 refusal and backward-compatible persistence. The existing all-orders preference round trip and real atomic session-file test now include nonempty preferred patterns.
