# Special file-type search — 2026-10-28

Independent adaptation of fd file-type filters, cohort repository #77 ([primary man page](https://github.com/sharkdp/fd/blob/master/doc/fd.1)). No upstream implementation copied.

Added `type:fifo` / `type:pipe`, `type:socket`, `type:block-device` / `type:block`, and `type:char-device` / `type:char`. The canonical saved forms are fifo, socket, block-device and char-device. These structural conditions are independent of text mode and do not contribute uppercase text to smart-case analysis. Repeated type conditions remain conjunctions, matching Commander’s established predicate model; this does not implement fd’s repeated-type OR syntax.

Native Unix search captures lexical mode type bits from metadata; links to special objects remain symlinks. New native indexes persist an optional file_type_bits fact, including known ordinary kinds. Older/non-Unix native snapshots without that fact cannot establish the filter and report skipped records. Invalid cached type codes are likewise treated as unknown. Rebuilding an old index captures current native kinds; no forced schema migration or cache rewrite is performed. ZIP inspection uses Unix external attribute type bits; TAR inspection recognizes FIFO/character/block header kinds without extracting or creating devices. TAR has no standard socket entry kind. Existing file, regular, symlink and executable semantics remain intact.

ZIP text inspection now skips stored special-file entries before decompression, joining existing native regular-file opening checks and TAR nonregular-content checks. Metadata-only special queries do not require text reads. Other predicates, saved JSON, expression round trips, query chips, name filtering and archive scope compose through the shared compiled metadata stage. The existing 640-byte index metadata overhead bound still passes with the extra optional fact.

Three new regressions cover parser aliases/case/canonical forms/JSON, an observed-bit matrix distinguishing every special kind from files/directories/links and unknown facts, and an all-mode native/index/ZIP/TAR matrix. The latter creates an actual FIFO and bound Unix socket, includes misleading ordinary names and links to FIFO/socket/device, patches ZIP central-directory Unix attributes (the writer strips type bits), creates safe zero-payload TAR special headers, and verifies kind results, archive scope, conjunctions, explanations and skipped content searches. It also removes cached facts and injects invalid codes to verify unknown coverage, and checks /dev/null’s native character-device metadata without opening it. No privileged device node was created: native block-device classification is covered by bit predicates and stored archive headers, not a real block-device fixture.
