# Edit selected file timestamps — 2026-10-31

Independent adaptation of [Double Commander Change Attributes](https://doublecmd.github.io/doc/en/help.html#cm_SetFileProperties), cohort #3. No upstream implementation was copied.

The command palette's **Change file timestamps** opens a worker-inspected preview for the captured selection or cursor. **Modified time** and **Accessed time** accept `YYYY-MM-DD` (midnight UTC) or RFC 3339 with an explicit offset and optional fractional seconds. Blank fields keep the current corresponding value. **Use current time** captures one instant for both drafts; **Keep existing times** clears both. Invalid values block Apply. Preview shows UTC before/after values; counts are cached against immutable rows and edits.

**Apply timestamps** runs through the shared metadata worker/mutation guards and protected non-following handles. Initial inspection requires the listing version; commit verifies the same object and rejects conflicting changes to edited fields. Unedited fields are omitted from the filesystem write, preserving their current values. Hard-link names share one physical object's times and repeated aliases become unchanged rows after the first successful edit. Filesystem precision differences are reported, not silently treated as exact success.

The report counts changed/unchanged/error rows and partial cancellation; Stop preserves changes already made. Reapplying requires **Reload timestamps**, which clears drafts and captures a fresh preview of the original same objects. It rejects replacement objects. Both panes refresh after a result. Permission editing keeps its original version checks and UI.

This transfer supports selected ordinary files and real directories on Unix through readable protected handles. Folder descendants are not enumerated or changed; recursive timestamp editing, birth/creation time, Undo and broader Change Attributes parity remain open. Symbolic links and unsupported/special objects block the preview. These are optimistic metadata checks, not a multi-file atomic transaction or an exclusion lock against concurrent external writers. The OS may update change time as part of changing metadata.
