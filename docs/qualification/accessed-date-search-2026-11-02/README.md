# Access-time date filters — 2026-11-02

Independent Commander extension combining [fd absolute-time filtering](https://github.com/sharkdp/fd/blob/master/doc/fd.1) (cohort #77) with [eza's separate accessed timestamp](https://github.com/eza-community/eza/blob/main/man/eza.1.md) (cohort #79). These exact filter names are Commander-specific; no upstream implementation copied.

Find and the shared Query model accept accessed-after: and accessed-before:. Boundaries are strict, accept the existing UTC date/RFC 3339 grammar, and share its nanosecond-resolution parser. Name matching modes do not change the numeric time comparison. Saved definitions validate and serialize the same typed predicates. Existing after:/before: continue comparing modification time. Explanations show the access-time condition and existing Find JSON exposes the captured access timestamp.

Live access time is captured from existing lexical metadata before content reads. Cached records add optional exact accessed_time with signed epoch direction, seconds and nanos. Legacy accessed_secs remains a seconds-precision fallback only when no exact record exists; corrupt exact records remain unknown instead of falling back. Serialization overhead is increased and its worst-case bound is tested. Restoring/indexed filtering adds no source I/O and stale cached observations survive source deletion. Unknown timestamps are counted as skipped. Archived members have no access-time observation: the existing grouping pivot may retain container atime, but the new member predicates never borrow it.

Tests cover strict equality, offsets, fractions, pre-epoch values, missing times, invalid boundaries and saved-query round trips in all match modes; live/cached provider parity, archived unknowns, stale cache hits and exact/legacy/corrupt cache observations.
