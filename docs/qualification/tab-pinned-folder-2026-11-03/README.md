# Pinned starting folders for tabs — 2026-11-03

Independent native Rust adaptation of cohort #4 [Krusader pinned tabs](https://docs.kde.org/trunk_kf6/en/krusader/krusader/folder-tabs.html): a tab permits temporary navigation and returns to its pinned address on reactivation. The context-menu checkbox and Pin/Unpin palette commands capture the pointed/current tab's folder. `[P]` marks pinned tabs. Closing protection remains the separately controlled existing option; pinning alone does not prevent closing.

Pinning does not navigate, list folders or replace the live owner. Switching away and back resets only the reactivated pinned tab. The return retires stale rows and queues remembered focus through the existing asynchronous listing controller; its remembered home filter/view/cursor/selection are restored in the running session. The current tab is not reset by clicking its already active label. Unpin leaves its current temporary location unchanged. Existing pending-operation/modal guards apply.

Pinned metadata follows duplicate/copy/transfer and closed-tab history. Sessions and workspace-profile tab layouts/exchange retain it. A restored active session/profile returns to its pin without synchronously scanning it, including when the saved temporary folder disappeared; an explicit launch path wins, including when it equals the saved temporary folder. Optional roots use platform-tagged native bytes/units (16 KiB bound), preserving non-UTF-8 identity. Missing/foreign/invalid/relative optional metadata is discarded without losing sibling tabs. A deleted pinned directory remains the requested path and produces an unavailable/empty actionable listing; it never falls back to stale rows. Pinning uses no path existence check, mount or background-folder read.

Five new regressions cover both pane directions, pin/unpin command availability, async return after a loading-frame cursor clamp, home filter/view/selection, invalid index and pending modal, duplicate/transfer/close/reopen, deleted home, native metadata limits, atomic session reopen/launch override and profile exchange/application. Seven final gates passed: audit, build, 3536 tests (0 failed, 3 ignored), Clippy, default check, formatting and diff. Default compilation retains its two preexisting warnings.

Native macOS Miller QA retains all earlier navigation/menu/group/drag checkpoints, then pins through the actual context menu, enters the highlighted child, switches to another tab and returns. Three independently verified receipts prove the temporary path and restored pinned path/cursor/three-item selection with exact tab metadata. All 14 framebuffer checks passed with zero external native effects; the final frame was visually inspected. The failed native runs and their source/check records are retained. They exposed two QA-driver issues: native activation could consume the first Columns click (now acknowledged with at most two targeted retries), and a deferred-close UI frame could overwrite a completed screenshot result with a timeout. The latter was proved by an existing frame file, a consumed screenshot token (zero pending probes) and the recorded final phase/request age. Terminal-result guards now stop input injection and timeout processing after completion; the original interaction/screenshot deadline is unchanged. An initially attempted callback-budget extension was removed after this diagnosis.
