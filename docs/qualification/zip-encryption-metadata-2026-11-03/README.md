# Declared ZIP encryption metadata

Independent adaptation of cohort #96 [PeaZip ZIP/ZIPX encryption support](https://peazip.github.io/encrypt-files.html), which distinguishes legacy ZipCrypto and WinZip AE. No external implementation was copied and no dependency was added.

Archive listing now records the declared method from parsed central-directory flags and AES extra fields. Member details show ZipCrypto or WinZip AES-128/192/256 and AE-1/AE-2 alongside the existing password requirement. CSV appends Encryption method, preserving its existing columns and the distinction between None for unencrypted ZIP and an empty field for unavailable TAR/synthetic metadata. These are declared, unauthenticated metadata; listing does not consume a password or decode payloads. Strong-encryption flag declarations are labeled Unknown rather than guessed to be ZipCrypto. Invalid/duplicate AES settings and contradictory AES/encrypted declarations have explicit labels. Structural parser refusals remain refusals; this does not add support for other encryption protocols.

Two new regressions cover all six AES strengths/versions using independently generated prior 7-Zip/OpenSSL fixtures and a mutated strong-encryption declaration. Existing raw unsupported-codec listing, UI details and CSV tests also verify labels and unavailable values. Native ArchiveMetadata preserves all ten earlier states and adds an eleventh AES-256 AE-2 state through real pointer input (36 phases); all eight rendered details must be visible for each saved observation. ArchiveExport rechecks five exact clipboard copies with the appended CSV field using the recording clipboard port.
