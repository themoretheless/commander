# Alternative filename patterns — 2026-10-28

Independent adaptation of alternative filename searches from [Double Commander Find files](https://doublecmd.github.io/doc/en/findfiles.html), whose File mask accepts several values. The syntax is adapted to Commander’s typed query model; no upstream code copied. This is an OR group for existing Exact/Fuzzy/Regex name matching, rather than a semicolon-separated glob mask implementation. fd’s additional `--and` patterns are conjunctions and are not the source of this OR behavior.

Repeat `anyname:`: `anyname:invoice anyname:receipt ext:pdf` accepts either name pattern while retaining the extension requirement. All occurrences coalesce into one group at the first occurrence’s position. Other predicates, ordinary repeated `name:` fields, and the independent `anycontent:` group combine through AND. Literal punctuation is not a list separator; standard query quoting applies. Name matching uses the basename, including archive member basenames, and does not itself require content reads.

Each alternative uses the current mode and global case policy. Smart case analyzes all members; regex validation compiles every member. Matchers compile once per query. First declared successful match provides the score, name ranges and explanation, without duplicating hits. Query chips show the OR group; expression/JSON saved representations preserve declaration order. A group accepts 1–64 nonempty patterns and at most 64 KiB of combined pattern text. Programmatic duplicate groups are rejected before smart-case parsing. Existing content-group bounds now share constant names and validation structure; their semantics remain covered by the complete suite.

Four new regressions cover grouping, canonical expressions and JSON, ordinary-name conjunction, empty/malformed/bounded/duplicate groups, all-member regex smart-case analysis, mode-specific behavior, punctuation, global case policy, mixed independent name/content groups and OR chips. A real native/index/ZIP/TAR matrix checks every matching mode, name alternatives plus extension filtering, negative name conditions, ordinary conjunction, smart case, content conjunction and content alternatives. Archive fixtures include nested members; a multi-matching invoice-receipt fixture verifies the first-declared name explanation and ranges.
