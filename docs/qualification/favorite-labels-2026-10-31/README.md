# Favorite display names and quick-jump assignment — 2026-10-31

Independently adapts [Nautilus bookmark label editing](https://help.gnome.org/gnome-help/nautilus-bookmarks-edit.html), cohort #22. No upstream application implementation is copied.

Favorites row context menus now contain a display-name field and **Save favorite name**, plus direct slot buttons 1–9. Name edits trim outer spaces, require 1–256 Unicode scalar values and reject control characters. They preserve the full original path, ordering and quick-jump binding. Invalid, unknown and unchanged edits do not save. This changes bookmark metadata; no folder is renamed or created. The original path remains available in the favorite's tooltip and quick-jump target.

Slot buttons reuse existing unique-slot ownership: assigning an occupied slot moves it from its previous holder; assigning the same slot again is a no-op. Existing move-up/down, clear-slot and remove actions remain. Both new edit types pass through the workspace's existing bookmark persistence owner and recovery gate. Existing persistence failure reporting is retained; this does not establish a new transactional rollback policy for in-memory metadata after a save failure.

The name is an explicit draft until Save/Enter; clicking elsewhere closes the menu without committing it. A later opening starts from the stored label. The menu now uses close-on-outside-click behavior so focusing/selecting/typing in the field does not close it. Explicit action buttons still close it after applying their action. Assigning a slot does not implicitly save an unsaved name draft.
