# One-search ZIP content password

Independent combination of cohort #96 [PeaZip encrypted archive access](https://peazip.github.io/extract-encrypted-files) and Commander's existing full-text archive search. The reference documents encrypted browsing/search; this milestone is an independent integration into Commander's content predicate, not a claim that PeaZip uses the same full-text implementation. No external code or dependencies were added.

Search offers an explicit ZIP password for next search toggle and masked field. Empty and Unicode passwords are valid. Enabling it pauses debounced automatic searches; Search launches one generation, consumes/clears the field and disables the toggle. A pending fresh-index rerun cannot consume a password while it is being entered, and a password-backed generation does not schedule an automatic index rerun that would lose its credentials. Closing or disabling the field drops its Zeroizing buffer; egui undo history is cleared each rendered frame. Query/history/report/saved-search/index schemas contain no password field.

The worker owns a Zeroizing password for one generation, lends bytes only to the shared verified ZIP reader and explicitly drops it before completion publication. Queued/abandoned/refused workers drop it normally. Live and indexed providers share the same archive path; decrypted member text is transient Inline content, never added to the persistent RootIndex. One supplied password is tried for all ZIP members in this generation; there is no per-archive prompt or password map. Missing/wrong passwords and authentication/CRC failures keep the existing content-skipped accounting and never produce a partial content match. Archive name-only queries still work without a password.

The existing 1 MiB member / 32 MiB aggregate text, 100000 members / 1024 archives and compression-ratio limits remain. ZIP raw reads and seeks now poll cancellation, with reads capped at 64 KiB, including AES authentication tails after codec EOS. Decoder memory/window/arena limits, overlap and contained-path checks remain shared. Cancellation is checked again before publishing a decoded member. This is not a new immutable-source integrity guarantee for Search; dedicated Test archive retains its separate source-stamp protocol.

Two Rust regressions qualify live/indexed wrong/correct/repeat behavior, exact archive identity, immutable serialized index and no extracted member file; the reader matrix covers all five custom codecs, three AES strengths and both versions (30 combinations), empty passwords, ZipCrypto LZMA/PPMd, authentication/CRC rejection, aggregate refusal and cancellation. Existing broad tests cover unencrypted paths and search behavior.

New native SearchPassword uses 42 raw pointer/text phases: no password, wrong password, correct Unicode password, repeat without a password, correct password again. Each completed state records exact query, paths, matched/skipped counts and empty/disabled password field. Native effects must all remain zero. ArchiveMetadata is recaptured as a regression. Earlier intermediate captures and failed lint diagnostics are retained separately from final qualification.
